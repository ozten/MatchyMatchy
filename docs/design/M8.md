## 0. What already exists (audit before building)

- **Profiles → severities:** DONE in `scoring.rs::ParityProfile::severity_for`. The spec §9 table
  (visual info/error, style warn/error, hygiene fail, a11y warn, content/structure fail) plus the
  M7 per-type overrides (accessibility_improved=info, console_error=warning, load_error/
  status_code_mismatch/missing_form=critical) are already wired and tested. **M8 adds no new
  severity mapping** — it only proves the switch flips pass/fail via a fixture (acceptance below).
- **Contract structs:** `Cluster`, `Suppressed`, `AgentSummary{cluster_count, top_fixes}` already
  exist in `contract.rs` and the JSON schema already permits `clusters`, `suppressed`, and
  cluster IDs in `topFixes`. **No contract/schema delta is needed.** M8 only *populates* fields
  that are currently hardcoded empty in `report/json.rs::assemble_diff_result`
  (`cluster_count: 0`, `clusters: []`, `suppressed: {0, []}`).
- **`--fail-on`:** flag + `compute_exit_code` exist but key off the 3-state `Status`
  (Critical/Error both collapse to `Fail`). M8 makes it severity-accurate.
- **JSON renderer:** DONE (`report/json.rs`). HTML/Markdown are absent.

## 1. Determinism contract for everything below (§3.3, §15)

All M8 code is in the analyze layer, so it is a pure function of the inputs and MUST be
byte-deterministic. Concretely:

- **No HashMap iteration.** Group with `BTreeMap<String, …>` keyed by a stable canonical string,
  or collect-and-sort. Never iterate `serde_json::Map` for ordering (it is insertion-ordered, but
  we never rely on it; we sort).
- **Total orders.** Every sort ends in a stable tiebreak on issue `id` / cluster `id`.
- **Fixed-order float reductions.** Cluster fix-value = `max` over members iterated in a sorted
  order; ties broken on id, so the chosen representative is deterministic.
- **IDs are content-addressed** (SHA-256 → `issue_`/`cluster_` + 12 hex), identical to the existing
  `issue::compute_issue_id` convention.

Acceptance: `matchy analyze` of the same two bundles twice → byte-identical DiffResult
(`determinism-check.py`), now including `clusters` and `--baseline`-suppressed output.

## 2. Clustering (`clustering.rs`) — spec §7.4

### 2.1 Rule (no inference, fixed)

> Group issues by **(type + changed style property)** OR **(type + landmark)**; emit a cluster only
> when the group size ≥ `clusterMin` (default **3**).

### 2.2 The double-clustering problem and the precedence rule

An issue can satisfy *both* rules (a `style_changed`/`font-family` issue also sits in a landmark).
If both fired, the 454 font-family issues of fixture 15 would land in a property cluster *and*
several landmark clusters — contradicting spec §13.1 fixture 15 ("→ **one cluster** referencing all
member issues"). Therefore:

> **Property clustering takes precedence. An issue placed in a property cluster is removed from the
> pool before landmark clustering runs. Each issue belongs to at most one cluster.**

This makes the global-style defect collapse to exactly one `font-family` property cluster, while
unrelated `visual_region_changed` issues (which have no changed style property) still cluster by
landmark. It also keeps clustering a *partition* of the clustered subset, which is what
`topFixes`'s "one work item, not hundreds" depends on.

### 2.3 Algorithm

Input: the **kept** (post-baseline) issue list, already merged across viewports, in any order.

```
fn cluster_issues(kept: &[Issue], cluster_min: usize) -> Vec<Cluster>
```

1. **Property pass.** For each issue, derive `style_property(issue)`:
   - `Some(p)` when `issue.category == Style` and `issue.remediation["property"]` is a string `p`.
     (This is exactly the property that entered the issue-id hash for style issues, so it is the
     authoritative "changed style property". Gradient issues carry no `property` and fall through —
     they are rare and never reach `clusterMin` anyway.)
   - else `None`.
   Group issues with `Some(p)` into a `BTreeMap<(IssueType, String/*p*/), Vec<String/*id*/>>`.
   Each group of size ≥ `clusterMin` becomes a **property cluster**; its member ids are removed
   from the pool. Sub-`clusterMin` groups are released back to the pool unclustered.
2. **Landmark pass.** Over the remaining pool, group by
   `BTreeMap<(IssueType, String/*landmark*/), Vec<id>>` where landmark = `anchors.landmark` and is
   non-empty. Groups of size ≥ `clusterMin` become **landmark clusters**.
3. For each emitted cluster, sort member `issueIds` ascending (stable). Build:
   - `id = "cluster_" + hex12( sha256( type.as_str() ⏎\x1f⏎ kind ⏎\x1f⏎ sharedKey ) )` where
     `kind ∈ {"prop","lm"}` (discriminator prevents a property named like a landmark colliding).
   - property cluster: `sharedProperty = Some(p)`, `sharedLandmark = None`,
     `summary = "{n} {type} issues share {p}"`.
   - landmark cluster: `sharedProperty = None`, `sharedLandmark = Some(lm)`,
     `summary = "{n} {type} issues in {lm}"`.
   `type`, `p`, `lm` are all controlled vocabulary (issue-type enum, `STYLE_DIFF_PROPERTIES`,
   landmark set) — **no page-derived strings in summaries**, so no escaping concern there.
4. **Order the `clusters` array** by `(descending member count, ascending id)` — total order, most
   impactful first.

`clusterMin` lives in `config.rs` as `CLUSTER_MIN: usize = 3` (spec default; config-overridable
later, like the other thresholds).

### 2.4 Why iteration is deterministic

`BTreeMap` keys are `(IssueType, String)`; `IssueType` derives `Ord`, so the map iterates in a
fixed key order independent of insertion. Member id vectors are sorted. The final array sort is a
total order. No float compares in grouping; the only float (`topFixes` representative value, §4) is
tie-broken on id.

## 3. Baseline accept-list (`baseline.rs`) — spec §7.4

### 3.1 Format & loader

`--baseline accepted.json` → JSON array of `{ "id": "issue_…", "note"?: "…" }`.

```
pub struct Baseline { ids: BTreeSet<String> }            // notes are advisory; ignored in matching
pub fn load(path: &Path) -> anyhow::Result<Baseline>     // parse, collect ids
impl Baseline { pub fn is_empty(&self); pub fn contains(&self, id: &str) -> bool; }
```

Matching is by **exact stable issue id** (§7.1 content-addressed id, including any `-2` collision
suffix). That is the whole point of content-addressed ids: a baselined intentional change keeps the
same id across re-captures, so it stays suppressed through the fix→re-run loop.

### 3.2 Where suppression happens

In `assemble_diff_result`, **before** scoring/status/clustering/agentSummary — partition every
issue into `kept` / `suppressed`:

- `suppressed` = issues whose id ∈ baseline. Record `Suppressed { count, ids: sorted }`.
- everything downstream (sort, cluster, byType, fixableNow, topFixes, per-viewport issue lists,
  per-viewport status, overall status) operates on `kept` only.

This honors spec §7.4 "suppressed from `issues` (and from scoring/status)".

### 3.3 Scores under suppression (the one subtle decision)

Per-category scores are computed inside `analyze_viewport` (count-based: `1/(1+n)`, except `visual`
which is `1 - page_changed_ratio`, a pixel measurement). assemble currently takes `min_per_category`
of the passed-in per-viewport scores.

Decision, golden-safe:

- **Empty baseline → scores untouched.** `min_per_category(passed scores)` exactly as today. This
  guarantees zero perturbation of every existing golden (all of which run with no baseline).
- **Non-empty baseline → recompute the count-based categories per viewport from that viewport's
  `kept` issues, keep that viewport's `visual` (ratio-based, not derivable from issues), then
  `min` across viewports.** Recompute rule mirrors the analyze formulas exactly:
  - content = `1/(1+ |kept where category==Content|)`
  - structure = `1/(1+ |category==Structure|)`
  - style = `1/(1+ |category==Style|)`
  - accessibility = `1/(1+ |type==AccessibilityRegression|)`  (improved excluded, as in analyze)
  - technical = `1/(1+ |category==Technical|)`  (network_error+console_error; status/load short-
    circuit or arrive via a separate ViewportAnalysis, never here)
  - hygiene = `1/(1+ |category==Hygiene|)`
  - visual = unchanged (carried from the viewport's analyze score)

  Recompute is **per-viewport then min**, so with an empty baseline it would reproduce the
  untouched path — the two paths are consistent; we branch only to avoid touching the well-tested
  no-baseline scores at all.

## 4. assemble_diff_result rewrite — ordering & topFixes (§7.2, §7.4)

New signature:

```
assemble_diff_result(run_id, old_url, new_url, profile, viewports, baseline: &Baseline) -> DiffResult
```

Pipeline (all deterministic):

1. Merge issues across viewports → `all`.
2. **Suppress:** `(kept, suppressed) = partition(all, baseline)`. `suppressed.ids` sorted asc.
3. **Sort `kept`** by descending fix value (`severityWeight × confidence × localityBonus`), tiebreak
   ascending id — unchanged from today (§7.2). This is the agent work queue / JSON order.
4. **Cluster** `kept` → `clusters` (§2). Build `id → cluster_id` lookup (`BTreeMap`).
5. **byType / fixableNow** over `kept` (BTreeMap; existing helpers).
6. **topFixes (cluster-aware, §7.4):** build a work-queue:
   - one entry per cluster: `(cluster.id, fv = max over members of fix_value)`,
   - one entry per `kept` issue **not** in any cluster: `(issue.id, fv = fix_value(issue))`.
   Sort by `(descending fv, ascending id)`, take first 5 ids. A cluster id in `topFixes` means
   "fix the shared root cause, clear the group." `fv` ties broken on id → deterministic
   representative.
7. **clusterCount** = `clusters.len()`.
8. **Per-viewport:** filter each viewport's issues to `kept`; `issues` = kept ids; `status` =
   `compute_status(kept severities)`.
9. **Overall status** = worst across viewport statuses (over `kept`).
10. **Scores** per §3.3.
11. Assemble `DiffResult { …, issues: kept (sorted), clusters, suppressed, agentSummary{…} }`.

## 5. HTML renderer (`report/html.rs`) — spec §11, §15

Static, self-contained `report.html` written at the out-dir root (screenshots are referenced by
the same relative paths already in `artifacts`/`viewports[].artifacts`, e.g. `desktop/old.png`).

### 5.1 Security invariants (§15 — non-negotiable)

- **Every page-derived string is HTML-escaped** before interpolation: issue `message`, all
  `anchors.*`, evidence values, remediation `from`/`to`/`grep`, urls, console/network text. One
  `escape(&str)` helper: `&→&amp; <→&lt; >→&gt; "→&quot; '→&#39;`. Applied at every interpolation
  site; there is no raw page string anywhere in the output. (Strings are already control-char-
  stripped + length-capped at capture, §4.3/§7.5, so escaping is the only remaining step.)
- **Restrictive CSP**, emitted as a `<meta http-equiv="Content-Security-Policy">`:
  `default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`.
  Scripts are fully blocked (`default-src 'none'` ⇒ no `script-src`). `img-src 'self'` allows the
  relative screenshot/crops; `style-src 'unsafe-inline'` covers the single inline `<style>`.
- **No inline event handlers, no `<script>`, no JS** anywhere. The report is fully static — no
  filters, no re-sort, no region-jump (spec §2 "v1 ships a static HTML page").

### 5.2 Layout (top-down, machine-then-human like the JSON)

1. `<head>`: charset, CSP meta, `<title>` (escaped url pair), inline `<style>`.
2. Header: status badge (pass/warn/fail/error), old→new urls (escaped), profile, run id,
   tool version.
3. `agentSummary`: fixableNow, clusterCount, byType list, topFixes (ids as plain text).
4. Scores: a 7-cell table (visual/content/structure/style/accessibility/technical/hygiene).
5. Per viewport: side-by-side `<img>` old | new | diff (the §12 "side-by-side screenshots"),
   each a thumbnail linking to the full image.
6. Clusters section: each cluster's summary, shared key, member count, member ids.
7. Issues section (in JSON fix-value order — the "fix-ordered issue list"): per issue a card with
   type, severity, confidence, goal, message, anchors (text/href/role/landmark/nearestHeading),
   evidence old/new, remediation (action, property, from→to, grep targets). All escaped.
8. Suppressed section: count + ids, when non-empty.

### 5.3 API

```
pub fn render_html(result: &DiffResult) -> String
pub fn write_html(result: &DiffResult, out_dir: &Path) -> anyhow::Result<()>   // out_dir/report.html
```

Pure string assembly from the `DiffResult` (no fs reads); deterministic.

## 6. Markdown renderer (`report/markdown.rs`) — spec §12

`report.md` at out-dir root. Plain GitHub-flavored markdown:

- `# matchy report` + status, urls, profile, run id.
- `## Summary`: fixableNow, clusterCount, topFixes, byType.
- `## Scores`: a markdown table.
- `## Issues` (fix-value order): a table (id | type | severity | goal | message) followed by, for
  fixable issues, the remediation grep targets. Page-derived cells are escaped for markdown table
  safety: `|`→`\|`, newlines→space, and wrapped where it reads as code (urls/props). Markdown is
  not executed, but we keep cells from breaking the table.
- `## Clusters`, `## Suppressed` sections.

```
pub fn render_markdown(result: &DiffResult) -> String
pub fn write_markdown(result: &DiffResult, out_dir: &Path) -> anyhow::Result<()>
```

## 7. CLI wiring (`bin/matchy.rs`) — spec §14

- New flags: `--baseline <path>` (Option<String>), `--html` (bool), `--markdown` (bool).
  `--json` already exists and JSON is always written.
- `run_full` and `run_analyze` both:
  - load baseline (`Baseline::default()` when absent),
  - pass it into `assemble_diff_result`,
  - after `write_diff_result`: if `--html` → `write_html`; if `--markdown` → `write_markdown`.
- **`--fail-on` becomes severity-accurate.** New `compute_exit_code(kept_issue_severities, fail_on)`:
  - `never` → 0.
  - else threshold ∈ {info, warning, error, critical}; exit 1 iff any kept issue has
    `severity.rank() >= threshold.rank()`, else 0. (`info` ⇒ any issue fails; `critical` ⇒ only
    critical fails — the distinction the old `Status`-based code couldn't make.)
  - Evaluated on **post-profile, post-baseline (kept)** severities, per §14.
  Exit codes remain: 0 pass / 1 threshold tripped / 2 tool error. The `status` field is unchanged
  and still drives display.

DoD has four clauses. Mapping:

### Rust unit tests (mechanical, in the new modules)

- clustering: property precedence over landmark; sub-`clusterMin` groups not clustered; member ids
  sorted; cluster array ordered by (count desc, id asc); ids stable/content-addressed; determinism
  under shuffled input.
- baseline: load/parse; partition; unknown ids ignored; empty baseline = identity.
- assemble: empty baseline ⇒ scores identical to pre-M8; suppression recompute matches formula;
  topFixes prefers cluster id over member ids and respects fix-value order.
- html: escape() correctness; rendered output contains CSP, no `<script>`, no `on*=` handler;
  a `"><script>` payload in an anchor text comes out escaped.
- markdown: table cell escaping; sections present.

- Interactive HTML (filters/sort/region-jump) — spec §2 defers to post-v1.

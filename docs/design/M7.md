Spec coverage: §11 (a11y diff via axe-core; network/console diff), §7.3 taxonomy
(`accessibility_regression`, `accessibility_improved`, `network_error`, `console_error`),
§4.3 (a11y extraction), §9 (profile severities — a11y = warn), §3.3 (determinism), §15
(invariants). DoD (§12 M7, verbatim): *"axe diff, network/console issue emission. New 404 asset
and new console error reported; seeded a11y regression detected."*

The contract enum, JSON-schema enums, and category set already include all four M7 issue types
(added at contract-design time); **no contract struct or schema changes are required.** M7 wires
up the emitters, the capture-layer signals they consume, the scoring, and two new fixtures.

## 1. What ships

**Analyze (Rust) — two new pure differs + scoring:**
- `network_diff.rs` → `network_error` (new-only failed / 4xx-5xx requests) **and** `console_error`
  (new-only error-level console messages). Both category **technical**.
- `a11y_diff.rs` → `accessibility_regression` / `accessibility_improved` over axe **rule sets**.
  Category **accessibility**.
- `lib.rs::analyze_viewport`: run both differs after the style diff; compute the `technical` and
  `accessibility` scores (currently hard-wired to `1.0`).
- `scoring.rs::severity_for`: `accessibility_improved` → Info, `console_error` → Warning
  (explicit per-type overrides; network_error keeps the technical-category default Error).
- `config.rs`: three new `base_confidence` constants. **M7-introduced, not under the M6 freeze**
  (the M6 freeze covers matcher/visual constants only); annotate as M7, calibratable at real use.

**Capture (TypeScript) — make the three signals real:**
1. **axe-core**: depend on `axe-core` (pinned), inject `axe.source`, run `axe.run` with
   `resultTypes:['violations']` **after screenshots + page-model extraction**, populate
   `bundle.page.a11y.violations`. Today it is hard-coded `[]`.
2. **Console-listener timing fix**: the console listener is attached *after* `stabilize()` returns
   (capture.ts:191), i.e. **after navigation** — so every load-time console message is dropped.
   Attach it **before `page.goto`** via an `onPageCreated` callback threaded into `stabilize`.
3. **Reliable network status**: add a `context.on("response")` listener that records
   `resp.status()` synchronously (replacing the fragile fire-and-forget `await req.response()` in
   `requestfinished`), so 4xx/5xx statuses are present deterministically.

**Testbed — two new variants + re-record:**
- `v20-console-error` (:3020): new page logs a console error absent on old → `console_error`.
- `v21-a11y-lang` (:3021): new page drops `<html lang>` → axe `html-has-lang` →
  `accessibility_regression`.
- `v12-image-404`: now additionally emits `network_error` (its `expected-issues.json` already
  anticipates this via `anyOfTypes:["broken_image","network_error"]`). Golden re-record only —
  no expectation change.

## 2. Network / console diff (`network_diff.rs`) — §11

Signature:
```rust
pub fn network_console_issues(
    old_bundle: &CaptureBundle,
    new_bundle: &CaptureBundle,
    viewport: &str,
    profile: &ParityProfile,
    env_mismatch: bool,
) -> Vec<Issue>
```

### 2.1 `network_error` — new-only failing requests
A request **fails** iff `failed == true` **OR** `status >= 400`. `status == 0 && !failed` is
*unknown / not-yet-resolved*, **never** a failure (avoids false positives from any residual async
race). CORS / mixed-content manifest as `failed` or a 4xx/5xx status, so this rule covers them.

**New-only** via an origin-normalized key so the old (:3000) and new (:30xx) servers compare on
path, while third-party assets compare on absolute URL:
```
request_key(url, own_final_url):
  if url starts with origin(own_final_url): return path+query of url   // same-site → origin-relative
  else: return url                                                     // third-party → absolute
```
- `old_failing: BTreeSet<String>` = `request_key(r.url, old_final_url)` for every failing old req.
- For each failing **new** req, `k = request_key(r.url, new_final_url)`; if `k ∉ old_failing`,
  it is a candidate. Dedup by `k`, **sort by `k`**, emit one issue per unique key.
- Requests failing on **both** sides are suppressed (spec §11: "failures on both are noted but not
  scored against the new page"). v01–v19 reference the same static `site/`, so the only new-only
  failure in the whole testbed is v12's deleted image. External/unreachable URLs fail symmetrically
  → suppressed.

**Anchor:** map the failing new URL to a new-page `SemanticNode` whose `src` (image) or `href`
(link) equals the **absolute** request URL; borrow that node's anchors + `node_pair`-style locator
(rich `nearestHeading`). First match by node id; none → `Anchors::null()`. `goal = "G7"` always
(G7 = broken links/images/**assets**). For v12 this rides on the image node → `nearestHeading`
"Branded Call performance analytics", satisfying that variant's matcher.

**Severity** technical → Error. **Confidence** `base_confidence::NETWORK_ERROR = 0.95` through
`compute_confidence` (lazy-load timing can affect whether the request fired → env/determinism
multipliers apply).

**evidence** `{ "old": {url|null, status|null}, "new": {url, status, failed, type} }`
(old side = the matching non-failing old request if present, else null).
**remediation** `{ action:"restore_asset", findBy:{grep:[filename], near:nearestHeading},
from:url, to:null, note:"Asset returned HTTP <status> on the new page (loaded on the old page)…" }`.

### 2.2 `console_error` — new-only error console messages
Filter new/old console to `level == "error"`. **Exclude resource-load-failure lines** (text
starting `"Failed to load resource"`): those are the network differ's job (spec §11 splits
"4xx/5xx assets" = network from "uncaught exceptions" = console), and excluding them keeps v12 to a
single `network_error` rather than double-counting. Documented, deterministic, locale-scoped to the
testbed's English Chromium build.

- `old_errors: BTreeSet<String>` of message `text`.
- For each new error message, if `text ∉ old_errors`: candidate. Dedup by `text`, **sort by
  `text`**, emit one issue per unique text.
- Symmetric console noise (load-time errors now captured on *both* sides thanks to the timing fix)
  is suppressed by the new-only rule.

**Anchor:** none — a console message is not a DOM node. `Anchors::null()` (Low strength; spec §5
says weak-anchor issues are flagged harder-to-locate, never given fake identity — do **not** stuff
the message into `anchors.text`). `goal = None`. **Severity** Warning (proportionate; console noise
is a yellow flag, not a hard fail — explicit override in `severity_for`). **Confidence**
`CONSOLE_ERROR = 0.9` through `compute_confidence`.
**evidence** `{ "new": {level, text}, "old": null }` (text in `evidence.new` so the fixture matcher
`newContains` can assert it). **remediation** `{ action:"investigate_console_error",
findBy:{grep:[text]}, note:"…" }` — greppable by message text even with a null anchor.

## 3. A11y diff (`a11y_diff.rs`) — §11

Signature mirrors the network differ. Inputs: `old_bundle.page.a11y.violations`,
`new_bundle.page.a11y.violations` (`Vec<serde_json::Value>`, raw axe violation objects).

**Granularity = rule-level set diff** (spec literally says "diff violation **sets**"). A violation
"set" is the set of axe rule ids with ≥1 violation. Per-node granularity is **not** used in v1:
axe `node.target` selectors are unstable across a DOM rewrite (false regressions on real
migrations — M6 territory), and rule-level diffing has a decisive property that **bounds the
blast radius on v01–v19**: a rule that already fails on the golden page (a real marketing site
trips several) stays "present on both" under any restyle, so v05/v06/etc. emit **no** a11y
regression unless they introduce a rule the golden did not already fail. Node detail lives in
`evidence`. (Per-node delta is a noted post-v1 refinement.)

- `old_rules: BTreeSet<String>` = `violation["id"]` over old violations.
- `new_rules: BTreeSet<String>` similarly.
- **`accessibility_regression`**: `id ∈ new_rules \ old_rules`. Sorted by `id`.
- **`accessibility_improved`**: `id ∈ old_rules \ new_rules`. Sorted by `id`.

Parse each axe violation defensively: `id`, `impact`, `help`, `helpUrl`, `tags[]`, `nodes[]`
(each `target[]`, `html`). Missing fields default to null/empty — never panic on shape drift.

**Anchor:** best-effort — take the first new violating node for the rule; if its `target` (a CSS
selector) exactly equals a new-page `SemanticNode.css_selector`, borrow that node's anchors;
otherwise `Anchors::null()`. (For `html-has-lang`, `target == ["html"]` → null/page-level, which is
correct and honest.) `goal = "G8"` for both directions.

**Severity:** `accessibility_regression` → Warning (§9 a11y = warn, both profiles).
`accessibility_improved` → **Info** (an improvement is not a defect → never affects status; explicit
override in `severity_for`). **Confidence** `A11Y = 0.95` through `compute_confidence`.

**evidence** (regression):
```jsonc
{ "ruleId": "html-has-lang", "impact": "serious", "helpUrl": "…",
  "old": { "present": false },
  "new": { "ruleId": "html-has-lang", "impact": "serious", "nodeCount": 1,
           "nodes": [ { "target": ["html"], "htmlSnippet": "<html …>" } ] } }
```
`ruleId` is duplicated inside `evidence.new` so the fixture matcher `newContains:"html-has-lang"`
works without touching the shared harness. For `accessibility_improved`, swap old/new (rule lives
in `evidence.old`, `evidence.new` carries `{present:false}` — keep it non-null so `oldContains`
works). **remediation:** regression → `{ action:"fix_accessibility_violation",
findBy:{grep:[token]}, ruleId, helpUrl, note:"axe rule <id> now fails on the new page…" }`;
improved → `null`.

## 4. Scoring & wiring (`lib.rs`, `scoring.rs`)

In `analyze_viewport`, after the style diff and before `resolve_id_collisions`:
```rust
let network_issues = network_diff::network_console_issues(old, new, vp, profile, env_mismatch);
let technical_issue_count = network_issues.len();                 // network_error + console_error
let a11y_issues = a11y_diff::a11y_issues(old, new, vp, profile, env_mismatch);
let a11y_regression_count = a11y_issues.iter()
    .filter(|i| i.issue_type == IssueType::AccessibilityRegression).count();
issues.extend(network_issues);
issues.extend(a11y_issues);
```
Scores (replacing the two `1.0` literals), matching the established `1/(1+n)` pattern:
```rust
technical:     1.0 / (1.0 + technical_issue_count as f64),
accessibility: 1.0 / (1.0 + a11y_regression_count as f64),   // accessibility_improved excluded
```
The hygiene short-circuit path (status_code_mismatch, v18) is **unchanged**: it returns before the
content differs and keeps `technical: 0.0`, `accessibility: 1.0` — network/console/a11y are not run
against a 404 error page.

`severity_for` (add at the top, before the category match):
```rust
if *issue_type == IssueType::AccessibilityImproved { return IssueSeverity::Info; }
if *issue_type == IssueType::ConsoleError { return IssueSeverity::Warning; }
```

`agentSummary.byType`, `topFixes`, `fixable_now`, per-viewport status, and final fix-value sort all
flow automatically from the merged issue list — no change needed.

### Determinism (§3.3 / §15)
- All set membership via `BTreeSet`; all emitted lists **collected then sorted** by a stable key
  (network: request_key; console: text; a11y: rule id) before emission. No HashMap, no reliance on
  axe's or the bundle's request/console/violation ordering.
- Fixed-order float reductions already in `Scores`. New scores are scalar `1/(1+n)`.
- Capture may write violations in any order; analyze imposes the order. Identical bundles →
  byte-identical DiffResult.

## 5. Capture layer

### 5.1 axe-core (`capture.ts`)
- `package.json` deps += `"axe-core": "<pin>"` (use whatever exact version npm resolves; record it).
  Use **`axe-core` directly, not `@axe-core/playwright`** — the wrapper does a runtime
  `fs.readFileSync(require.resolve('axe-core/...'))` that cannot be flattened into `capture.cjs`
  (same class of problem as playwright-core's driver resolution, spec §14). `axe-core`'s `.source`
  property is the injectable script string and bundles cleanly through esbuild.
- After screenshots (capture.ts:254-255) and page-model extraction, **before** assembling the
  bundle:
  1. If a clock was installed, `await page.clock.resume()` — axe's internal `setTimeout`-based
     async machinery will **hang under a frozen clock**; `resume()` restores natural time. axe runs
     last, so resuming cannot affect the already-captured screenshots/styles/model. (Verify
     `resume()` exists in Playwright 1.60; it was added 1.45.)
  2. `await page.addScriptTag({ content: axeSource })` then
     `await page.evaluate(async () => await window.axe.run(document, { resultTypes: ['violations'] }))`.
  3. Wrap the whole thing in the existing Node-side deadline pattern (~20s) and a try/catch: on
     timeout/error, `violations = []` and `log(...)` — **never fail the capture** (graceful
     degradation → empty a11y diff).
- Assign `a11y: { violations }` into the bundle (replacing `{ violations: [] }`).
- Threat model: axe results are page-derived → already covered by the untrusted-data invariant
  (renderers escape; analyze only string-compares). We store `id/impact/help/helpUrl/tags/nodes`
  verbatim; node `html` is length-capped on the analyze side when copied into evidence.

### 5.2 Console-listener timing (`capture.ts` + `stabilizer.ts`)
- `stabilize(...)` gains a param `onPageCreated?: (page: Page) => void`, invoked immediately after
  **each** `context.newPage()` (the initial create at stabilizer.ts:95 **and** the retry create at
  :156). The callback resets `consoleMessages.length = 0` then attaches `page.on("console", …)` —
  so only the surviving (successful) page's console is recorded even if the retry-without-freeze
  path fires.
- **Remove** the post-stabilize `page.on("console")` attach at capture.ts:191 (now redundant; it
  was the bug — attached after navigation).
- Net effect: load-time console errors (the common case, and v20's seeded one) are captured.

### 5.3 Reliable network status (`capture.ts`)
- Add `context.on("response", (resp) => { /* find entry by resp.url(); set status = resp.status() */ })`.
  The response event carries the final status synchronously. Keep `requestfailed` (sets `failed`).
  Drop the fire-and-forget `await req.response()` block inside `requestfinished` (now redundant).
- HTTP 404 is a *completed* transaction → `response` fires with `status()==404`,
  `requestfailed` does **not** fire → entry `{status:404, failed:false}`; the differ's
  `status>=400` rule catches it.

### 5.4 Tests (vitest)
- console timing: a stub page that logs an error during `goto` is captured (listener attached
  pre-nav). (Use the existing test harness style.)
- network status: a `response` with status 404 sets the matching entry's `status`.
- axe: smoke test that `axeSource` is a non-empty string and `violations` is wired into the bundle
  shape (full browser axe run is exercised by the fixture gate, not unit tests).

## 7. Golden discipline

- **v12-image-404**: behavior change (adds `network_error`) — the *expectation* already anticipates
  it (`anyOfTypes` includes `network_error`; nothing forbidden by adding it), so this is a **golden
  re-record only**, not an expectation change. Still: changelog entry (what changed, why — the M7
  network differ now emits the asset failure the fixture always allowed) + golden-auditor **APPROVE**
  before re-recording, per CLAUDE.md (re-recording byte goldens after an approved behavior change).
- **v20 / v21**: brand-new variants — author `expected-issues.json` as intent (above), pass the
  intent check, then record fresh goldens. New variants need no auditor verdict for their *first*
  golden (nothing pre-existing changed); the changelog gets a "new fixture" note.
- **v01–v19 regressions**: the empirical run (step §8) must show **zero** new a11y/network/console
  issues on existing variants. If any appears:
  - a *legitimate* new-only detection (e.g. a real new color-contrast rule on a restyle variant) →
    add it to that variant's `expected-issues.json` as an accepted co-detection → golden-auditor
    APPROVE → re-record. (Expected to be empty given rule-level diffing, but handled if not.)
  - a *flaky / nondeterministic* axe result → determinism bug → fix the code (sort, or restrict the
    axe rule scope as a documented decision); never silence by editing an expectation.

## 9. Risks
- **Frozen clock vs. axe** — `page.clock.resume()` before axe; graceful-empty on timeout. Primary
  implementation risk; verify the API and the run completes on the big golden page within deadline.
- **axe rule set drift / blast radius** — bounded by rule-level diffing + the golden already
  tripping common rules; confirmed empirically in §8 before goldens are recorded.
- **CSP blocking the v20 inline script** — fixture-builder checks; external-file fallback.
- **Network status race** — eliminated by the synchronous `response` listener.
- **esbuild bundling `axe-core`** — `.source` is a plain string property; verify the bundle builds
  and `window.axe` is defined after `addScriptTag`.

# M4 — Computed-style diff + anchor locator (G1, G4)

Spec sections covered: §4.4 (computed-style capture), §5 (anchor locator — already largely built in M3;
M4 extends it to ancestor candidates), §7.1 (style evidence/remediation), §12 M4 DoD, plus §3.3/§15
determinism invariants.

**DoD (spec §12, verbatim):** gradient-removal fixture yields `background_gradient_lost` with from/to;
a CSS color/spacing change yields `style_changed` with property-level from/to and a greppable anchor
(no component name claimed); a container `flex-direction`/`gap` change is detected.

## 2. Capture side (TypeScript)

### 2.1 Candidate set (spec §4.4, verbatim rule)

Candidates = every SemanticNode element, **plus each node's ancestor chain (parentElement walk) up to
and including its nearest landmark element** (fallback: up to and including `document.body` when no
landmark ancestor exists), deduplicated. Budget: `styleBudget` (default **2000**) total entries in
`computedStyles`; on overflow drop **deepest-DOM-depth ancestors first** (tie-break: later document
order first), never drop SemanticNode entries; record truncation.

Implementation constraint: Playwright `page.evaluate` cannot close over imports, so the extraction
logic lives **inside the existing in-page extraction function in `extract/page-model.ts`** (same pass
that builds nodes — element refs are in scope there). Pure helpers that don't need DOM (the curated
property list, value capping) may live in `extract/computed-style.ts` and be inlined/duplicated into
the in-page function; correctness over module aesthetics.

### 2.2 Curated property set (read via `getComputedStyle(el).getPropertyValue(p)`)

```
color, background-color, background-image, background,
border, border-radius, box-shadow,
font-family, font-size, font-weight, line-height, letter-spacing, text-align,
padding-top, padding-right, padding-bottom, padding-left,
margin-top, margin-right, margin-bottom, margin-left,
display, position, opacity,
flex-direction, justify-content, align-items, gap, grid-template-columns
```

Values: cap at 1000 chars, strip control characters (same sanitizer as text). No color
re-normalization needed at capture (computed values are already canonical `rgb()`/`rgba()`); Rust
side normalizes defensively before compare.

### 2.3 Ancestor descriptors and ids

- If an ancestor element **is** a SemanticNode element, reuse the node id (no duplicate entry).
- True ancestors get ids `anc_<N>`, N assigned in **document order** over the deduped ancestor set
  (deterministic).
- Per ancestor, emit a descriptor:
  - `id`, `tag` (lowercase), `bbox` `[x,y,w,h]` (rounded ints, same convention as nodes), `depth`
    (distance from document root — used for budget drop order),
  - `cssSelector` — reuse the existing landmark-relative `buildSelector`,
  - `anchors` — full §5 anchor object: `text: null, role: null, href: null, alt: null,
    ariaLabel: null`, `nearestHeading` = text of the **first heading element contained within** the
    ancestor (document order); if none contained, fall back to the same preceding-heading rule used
    for nodes; `landmark` = nearest enclosing landmark name (itself if it is one);
    `ordinalInLandmark` = 1-based document-order index of this ancestor among ancestor candidates
    sharing the same landmark.

### 2.4 Bundle delta (the seam)

`CaptureBundle.computedStyles` becomes populated: `{ "<nodeId|ancId>": { "<prop>": "<value>" } }`.
New top-level field:

```jsonc
"styleCandidates": {
  "ancestors": [ { "id": "anc_7", "tag": "div", "bbox": [0,0,1440,720], "depth": 5,
                   "cssSelector": "main > div", "anchors": { /* §5 anchor object */ } } ],
  "chains": { "node_42": ["anc_9", "anc_7", "anc_1"] },   // nearest → furthest (landmark/body last)
  "budget": 2000,
  "truncated": false,
  "droppedCount": 0
}
```

Contract deltas: `contract/capture-bundle.schema.json` adds `styleCandidates` (required, since our
capture always emits it); `packages/capture/src/schema.ts` adds the zod mirror;
`packages/analyze/src/contract.rs` adds `StyleCandidates`/`AncestorDescriptor` structs with
`#[serde(default)]` on the `CaptureBundle` field so existing unit-test bundles still deserialize.
`ancestors` sorted by id-order (document order); `chains` keys are node ids (BTreeMap on Rust side).

TS tests: zod round-trip of the new block; helper tests for the property list/cap. Integration
coverage comes from the testbed fixtures.

## 3. Analyze side (Rust) — new module `style_diff.rs`

Pure function, mirrors `semantic_diff::semantic_issues` signature:

```rust
pub fn style_issues(
    old_bundle: &CaptureBundle, new_bundle: &CaptureBundle,
    match_outcome: &MatchOutcome, viewport: &str,
    profile: &ParityProfile, env_mismatch: bool,
) -> Vec<Issue>
```

### 3.1 Leaf channel

For every pair with `band == Matched` (Uncertain pairs are excluded — no style verdicts on uncertain
identity): look up both sides in `computedStyles` (skip pair if either side absent). Diff over the
**diff property list** = curated set **minus the `background` shorthand** (covered by
`background-color`/`background-image`; avoids double-reporting — the forbidden assertion in v06 is
exactly this class of bug). `border` shorthand stays in the diff list (no border longhands captured).

Compare after normalization: trim + collapse internal whitespace; if both values parse as a single
CSS color, compare canonical color form (`normalize_color`: `#fff`/`white`/`rgb(255,255,255)`/
`rgba(r,g,b,1)` → one canonical `rgb(r, g, b)` / `rgba(r, g, b, a)` form — spec §4.4; unit-tested).

Per differing property, classify:

- `background-image`: parse both sides with the gradient parser (§3.3 below).
  - old has ≥1 gradient, new has none → **`background_gradient_lost`**
  - both have gradients, normalized values differ → **`background_gradient_changed`**
  - otherwise → `style_changed`
  - Emit exactly **one** issue per (pair, property) — a gradient issue suppresses the generic
    `style_changed` for that property (v06 forbidden assertion).
- any other property → **`style_changed`**.

### 3.2 Ancestor channel (container properties — G1 gap/flex, G4 hero gradient)

Ancestors are not matched by the §6 matcher; pair them through their matched descendants:

1. Build `old_id → new_id` over `band == Matched` pairs.
2. For each old ancestor `a` (from `styleCandidates.chains`, old side): `D(a)` = set of matched old
   node ids whose chain contains `a`, **projected** to new ids, sorted. Skip if empty. Skip any
   chain entry whose id is a SemanticNode id (leaf channel owns those; unmatched-node ids are
   skipped entirely).
3. For each new ancestor `b`: `D(b)` = sorted set of matched new node ids whose chain contains `b`.
4. Group old ancestors by `D(a)` key (ids joined by `\x1f`) and new ancestors by `D(b)`; for each
   key present on both sides, pair within the group by **style-similarity assignment**:
   `sim(a,b)` = fraction of diff-list properties with equal normalized values (both-side-present
   props only) + 0.05 bonus if tags are equal — **uncapped** for ordering. Candidate pairs sorted by
   (sim desc, old id asc, new id asc) — sim rounded to 4 decimals first — greedily paired; pairs
   below `ANCESTOR_MIN_SIMILARITY = 0.6` are rejected. (Original design capped sim at 1.0 before
   ordering; that was a defect — a perfect pair, 1.0 + bonus, and a one-prop-differing pair,
   0.9615 + bonus, both capped to exactly 1.0, tied, and let greedy pairing cross nested cousin
   wrappers sharing a descendant set, emitting phantom `position` diffs that drifted the v08/v10
   goldens. The value *reported* in `evidence.match.score` is still capped at 1.0; `signals`
   carries the base ratio as `styleSim` and the bonus as `tagBonus`.) Unpaired ancestors emit **nothing** (never
   missing/added — this is what keeps v13's added `display:contents` wrapper silent).
5. Each paired (a, b) diffs exactly like the leaf channel (same classification, including gradients —
   v06's hero wrapper arrives here).

Rationale recorded for the reviewer: descendant-set pairing is invariant to wrapper insertion/removal
and to content edits (unmatched nodes are excluded from both sides' sets), and the similarity floor
prevents a misaligned pair from flooding false property diffs. In the v03–v06 variants the DOMs are
byte-identical (CSS-only edits), so every group pairs 1:1 trivially.

### 3.3 Gradient parser (Rust, unit-tested per §13.3)

Parse a computed `background-image` value: top-level comma split (paren-aware — `rgb(…)` contains
commas) into layers; a layer matching `linear-gradient(` / `radial-gradient(` / `conic-gradient(`
(also `repeating-*` variants) parses to:

```rust
struct GradientSpec { kind: String /* linear|radial|conic|repeating-… */,
                      angle: Option<String> /* "90deg" | "to right" | None */,
                      stops: Vec<GradientStop> /* { color: String, position: Option<String> } */ }
```

Tolerant by design: angle/direction prefix optional (Chromium omits default direction in computed
values); stop = color token (paren-aware) + optional position token(s). Unparseable gradient layers
degrade to presence-only (kind + raw string, empty stops) — classification still works; never panic.
Parsed specs go into `evidence.gradient = { "old": [...], "new": [...] }` on gradient issues
(stop deltas are first-class, §4.4).

### 3.4 Issue construction (every field)

- `id`: `compute_issue_id(type, viewport, old_anchors, Some(property))` — property is the CSS
  property name (gradient issues: `"background-image"`). Anchors are the **old side's** (node or
  ancestor descriptor).
- `category`: `style`; `severity`: `profile.severity_for(...)` (warn under default profile);
  `goal`: `"G4"` for the two gradient types, `"G1"` otherwise; `locale`: old page lang (existing
  convention).
- `confidence`: `compute_confidence(base, env_mismatch, old_det, new_det)` with new constants
  `base_confidence::STYLE_CHANGED = 0.9`, `base_confidence::GRADIENT = 0.95`.
- `locator`: old anchors; cssSelectorOld/New, bboxOld/New from both sides (ancestors have these in
  their descriptors); seqIndexOld/New for leaf pairs, `None` for ancestors.
- `evidence`:
  ```jsonc
  { "old": { "<property>": "<old value>" },
    "new": { "<property>": "<new value>" },
    "match": /* leaf: { stage, score, signals } from the pair (existing semantic_diff convention);
                ancestor: { "stage": "ancestor", "score": <sim>, "signals": { "descendantSet": 1.0, "styleSim": <sim> } } */,
    "gradient": { "old": [...], "new": [...] }   // gradient issues only
  }
  ```
- `remediation` (spec §7.1 semantics — `from` = current/new, `to` = desired/old):
  ```jsonc
  { "action": "restore_css_property",
    "findBy": { "grep": [/* quoted href if present, text if present; else nearestHeading if present; else [] */],
                "near": "<nearestHeading or null>" },
    "property": "<css property>",
    "from": "<new value>", "to": "<old value>",
    "note": "<one sentence; never names a component>" }
  ```
- `message`: e.g. `"font-size changed from 60px to 48px on heading \"Reach more…\""` /
  `"Background gradient lost on container near \"Reach more…\""`.

### 3.5 Wiring (`lib.rs`)

After `semantic_issues`, call `style_issues`; extend issues (visual ++ content ++ **style** ++
hygiene — final order is the report's fix-value sort anyway). `scores.style = 1.0 / (1.0 + style_issue_count)`
(mirrors content). Short-circuit path untouched (style stays 1.0 there).

### 3.6 Determinism (review checklist for every diff)

- All keyed iteration over `BTreeMap`/sorted `Vec` — `computedStyles` and `chains` are already
  `BTreeMap`; descendant-set keys are sorted joins; group iteration over `BTreeMap<String, …>`.
- Greedy assignment ordering is total: (rounded sim desc, old id, new id).
- No float accumulation across unordered collections; sims are ratios of counts.
- Same bundles twice → byte-identical DiffResult (determinism-check gains a style variant, v06).

## 4b. Post-verification design deltas (added during gap-closure)

Two defects surfaced by the first full testbed run, both resolved as code fixes:

1. **`url()` origin normalization (analyze).** Computed `background-image` absolutizes relative
   URLs against the page origin, and old/new always live on different origins (that is the tool's
   premise — different hosts, or different localhost ports in the testbed). Raw string comparison
   therefore false-positives on every element with a same-site `url()` background (16 issues on the
   v01 control). Fix: before comparison (and inside ancestor `style_similarity`), rewrite each
   `url(...)` token whose URL's origin equals **that side's own page origin** (from
   `page.finalUrl`) to its path+query, then strips **that side's page-directory prefix** when the
   path starts with it (v14 mounts the byte-identical site under `/products/connect/branded-call/`,
   so absolute paths differ while page-relative references are identical; `norm_href` itself returns
   the host-stripped absolute path and cannot change without drifting recorded M3 goldens — its doc
   comment's "relative to the page's directory" claim is recorded as an open M3 divergence).
   Cross-origin URLs stay absolute. Evidence/remediation keep the raw captured values. §3.3's
   mandate: environment/mount-induced variation must never silently flip verdicts.

2. **Ancestor anchor-text inheritance (capture).** Styled wrappers like
   `<a class="button_wrap"><div class="button_content"><div>See pricing…</div></div></a>` carry the
   defect on a container with no own text, yielding `text: null` / medium-strength anchors even
   though the contained text identifies the element precisely (§5: anchors are the element's
   *visible text* facts). Rule: an ancestor whose subtree contains **exactly one** text-bearing
   semantic node inherits that node's anchor text as `anchors.text`; zero or multiple text-bearing
   descendants → `text: null` (the v06 hero wrapper and v19 badge grid stay null). Only `text` is
   inherited — never `href`/`role`/`alt`, which would misrepresent the container.

3. **`auto` margins read via Typed OM (capture).** Chromium's `getComputedStyle` resolved value
   for `margin: auto` proved unstable across captures of byte-identical pages: empirically 0px,
   104px (stale used value from a prior layout generation, e.g. mid-lazy-scroll scrollbar state),
   or 120px (fresh used value) for the same element with an identical final bbox. This is §3.3
   leak-class nondeterminism in the rendering environment, and used-value margins are layout
   facts already covered by bbox/visual signals — G1 wants *authored* margin deltas. Fix: read
   the four `margin-*` properties via `el.computedStyleMap()` (Typed OM, Chromium-only — the
   only engine in scope), which yields computed values: `auto` serializes as `"auto"`
   (deterministic), authored lengths still resolve to px. Fallback to `getComputedStyle` if the
   Typed OM read throws. Other properties keep the `getComputedStyle` read; the same staleness
   class theoretically touches percentage paddings — accepted as out of M4 scope and noted here.

Verification also confirmed two v19 expectation-authoring errors (fixed before its initial audit:
the checker is case-sensitive and the heading renders uppercase via CSS `text-transform`; Chromium
serializes computed `gap` collapsed to `"32px"` when row equals column), and one accepted v19
knock-on to declare: `style_changed(grid-template-columns)` on the same grid — computed track sizes
re-resolve when the column gap changes.

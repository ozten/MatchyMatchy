Spec: `docs/prds/page-pair-diff-spec.md` §12 M2, implementing §10 (10.1 URL/redirect/canonical,
10.2 locale path, 10.3 egress policy), governed by §3.3 (determinism), §7 (contract), §15

## 1. Scope and DoD

old-200/new-404 produce the correct hygiene issues with correct remediation.

## 2. Architecture decision: where probing lives

§10.3's probes (extracted-link redirect following) are network I/O. The seam rule (§3.3) is
"capture never decides what is an issue; analyze never re-fetches or re-renders." Therefore:

- **The TS capture layer performs all probing**, gated by the egress policy at the point of
  egress, and records raw facts in the bundle (`page.linkProbes`). Probing runs **only when
  `CaptureConfig.probeLinks` is true**; the orchestrator sets it for the **new** side only
  (hygiene issues are remediation work on the new site; old-side probes have no consumer).
- **The Rust analyze layer derives issues** purely from the two bundles. It treats the bundle as
  ground truth but applies a **defensive egress guard** when consuming probe records (scheme must
  be http/https; URLs whose host is a private/loopback/link-local/metadata IP *literal* are
  ignored unless the page's own final URL host is such a literal or `localhost`). DNS-based
  refusal can only live in capture (a pure function cannot resolve names); this split is the
  honest reading of §13.3's "egress policy" unit-test line: TS tests the fetch gate end-to-end,
  Rust tests the scheme/scope/IP-literal guard.

This keeps `(bundle_old, bundle_new) → DiffResult` pure and the byte-exact golden suite intact.

## 3. Contract deltas

### 3.1 `CaptureBundle` — `page.linkProbes` (new, required) and `CaptureConfig.probeLinks`

`contract/capture-bundle.schema.json`, zod (`schema.ts`), and Rust (`contract.rs`) all gain:

```jsonc
// page.linkProbes: LinkProbe[] — always present; [] when probing disabled or no candidates.
// Sorted ascending by "url" (byte order), deduped. additionalProperties: false.
{
  "url": "http://localhost:3017/start",   // absolute, fragment-stripped, redacted (redactParams)
  "redirectChain": [                       // one entry per hop (pre-redirect URLs), like page.redirectChain
    "http://localhost:3017/start", "http://localhost:3017/mid"
  ],
  "finalUrl": "http://localhost:3017/",   // null when skipped or errored before any response
  "status": 200,                           // final response status; null when skipped/errored
  "skipped": null,                         // null | "scheme" | "external-scope" | "private-address"
                                           //      | "cap-exceeded" | "redirect-blocked"
  "error": null                            // null | message (timeout, connection refused, …)
}
```

Rust: `#[serde(default)] pub link_probes: Vec<LinkProbe>` on `PageModel` (tolerates old bundles);
JSON schema marks it required (capture always emits it). `schemaVersion` stays `"1.0"`
(pre-release; no consumers of the old shape exist outside this repo).

`CaptureConfig` gains `probeLinks: boolean` (zod default `false`; Rust field
`probe_links: bool`). `build_capture_config` sets it to `prefix == "new"`.

### 3.2 `DiffResult`

No schema changes — all eight issue types are already in the `IssueType` enum and `Remediation`
is open (`additionalProperties: true`). New evidence/remediation shapes (§5.3 below) are
documented here, not schema-enforced (evidence is `additionalProperties: true` by design).

## 4. Capture layer changes (TS)

### 4.1 New module `src/probe.ts`

`async function probeLinks(pageModel, inputUrl, config): Promise<LinkProbe[]>`

1. **Candidate set:** all `nodes[].href` values, resolved absolute (they already are), fragment
   stripped, `redactParams` applied, deduped into a sorted array. Filter to **probe-eligible**:
   - scheme `http:`/`https:` (else record only if same-site-shaped? No — non-http(s) schemes are
     never same-site candidates; drop silently, they are page content not probe targets),
   - **same-site**: registrable domain (via `tldts`, new dependency) equal to the registrable
     domain of `inputUrl`. When either host is an IP literal or has no registrable domain
     (`localhost`), fall back to exact hostname equality. Non-same-site → record with
     `skipped: "external-scope"`, no fetch (per §10.1, external links get no default probing).
   - After the first `MAX_LINK_PROBES = 50` eligible entries (sorted order), record the rest as
     `skipped: "cap-exceeded"` — no silent truncation.
2. **Address blocking:** before fetching, `dns.promises.lookup(host, {all: true})`; if any
   resolved address is in 10/8, 172.16/12, 192.168/16, 169.254/16, 127/8, `::1`, `fd00::/8`, or
   an IPv4-mapped form of those → `skipped: "private-address"`, **unless** the input URL's own
   host resolves private (local fixture serving stays possible — then private targets are
   allowed). Resolution failure → record `error`, no fetch.
3. **Fetch:** `fetch(url, {redirect: "manual", signal: AbortSignal.timeout(5000)})`, never read
   the body (`response.body?.cancel()`). On 3xx with `Location`: resolve, push the pre-redirect
   URL onto `redirectChain`, re-run the **full egress gate** (scheme/scope/address) on the target
   (violation → `skipped: "redirect-blocked"`, keep partial chain), max 5 hops (overflow →
   `error: "too many redirects"`). Record final `status`/`finalUrl`.
4. **Concurrency:** worker pool of 4 over the sorted candidate list; results re-sorted by `url`
   before return (deterministic output regardless of completion order).

Wire into `capture.ts` after page-model extraction, only when `config.probeLinks`. Probe failures
never fail the capture.

### 4.2 Tests (vitest)

- Egress gate as a pure function (`decideEgress(url, inputUrlContext)`): scheme refusal
  (`file:`, `ftp:`, `javascript:`), scope refusal (other registrable domain; subdomain of same
  registrable domain accepted; `localhost` ↔ `127.0.0.1` host-equality fallback), private-range
  refusal incl. metadata range and the allow-when-input-private exception.
- Redirect-chain assembly with a mocked fetch: 2-hop chain ordering, hop-target re-gating, hop
  cap, fragment stripping, dedupe, sorted output, cap-exceeded records.

## 5. Analyze layer changes (Rust)

### 5.1 New modules

- `src/hygiene.rs` — `pub fn hygiene_issues(old: &CaptureBundle, new: &CaptureBundle, viewport:
  &str, profile: &ParityProfile) -> HygieneOutcome`
  where `HygieneOutcome { issues: Vec<Issue>, short_circuit: bool }`.
- `src/locale.rs` — locale segment parser + embedded ISO 639-1 language set and ISO 3166-1
  alpha-2 region set (sorted `&[&str]`, `binary_search` lookups).
- `src/egress.rs` — the defensive guard of §2 (scheme + IP-literal ranges + host-scope), unit
  tested per §13.3.
- New dependency: `url = "2"` for parsing (host/path/scheme/query handling).

### 5.2 Checks, in fixed emission order (before global fix-value sort)

All checks evaluate the **new** side; the old side supplies the comparison baseline. (§10.1 says
checks "run on the two input URLs" — both sides are *computed* where parity needs them, but
issues are *emitted* only against the new page: hygiene issues are remediation work items for the
new site, and an old-site defect has no fix in the new site's source. Documented interpretation.)

1. **Status parity (short-circuit, checked first).** `old.page.statusCode` in 2xx AND
   `new.page.statusCode` not in 2xx (0 counts as non-2xx) → one `status_code_mismatch`
   (category `technical`, severity **critical** under both profiles — add a special case in
   `ParityProfile::severity_for`, like `LoadError`), `short_circuit: true`. When set,
   `analyze_viewport` still runs the visual differ to produce `diff.png` (artifact paths stay
   valid) but **discards every other issue** — the viewport's issue list is exactly this one
   issue ("the one decisive issue", §10.1). Both sides non-2xx → no issue, normal diff proceeds
   (comparing two error pages is legitimate parity). Old non-2xx / new 2xx → no issue
   (improvement).
2. **Trailing slash** (`TrailingSlashPolicy` enum in `config.rs`; default `Never`, constant —
   config file is deferred). Path of `new.page.finalUrl` ends in `/` and path ≠ `/` (root is
   exempt: the slash is not removable) → `url_trailing_slash`. `Always`: non-root path lacking a
   slash → issue. `Preserve`: new path's slash state ≠ old path's slash state → issue.
3. **Redirect chain.** `new.page.redirectChain.len() > 1` (≥ 2 hops; one entry per hop, spec
   §10.1 verbatim) → `url_redirect_chain`. The "redirect where none should occur" clause needs a
   configured expectation that doesn't exist until the §14 config file lands — deferred,
   documented here. Old-side chains: not emitted (see above).
4. **Protocol downgrade.** scheme(new.finalUrl) == `http` AND scheme(old.finalUrl) == `https` →
   `url_protocol_downgrade`. Per-link: a same-site link URL on the new page whose `https`
   twin (identical URL modulo scheme, host-stripped — see §5.4) exists on the old page →
   `url_protocol_downgrade` with the link node's anchors.
5. **Canonical.** `new.page.canonical` is `Some`, AND `resolve(canonical_raw, new.finalUrl)` ≠
   `normalize(new.finalUrl)` (normalize = strip fragment, apply trailing-slash policy: under
   `Never`/`Preserve` compare with non-root trailing slashes stripped from both sides), AND
   **not parity-suppressed** → `canonical_mismatch`. Parity suppression: `old.page.canonical`
   (raw attribute, as captured) is byte-equal to `new.page.canonical` → suppress. Rationale: the
   testbed golden carries a relative `canonical="branded-call.html"` on *both* sides of every
   pair; an identical raw canonical is a pre-existing condition, not a migration defect — the
   §11 "failures on both are noted but not scored against the new page" principle applied to
   hygiene. This is what keeps v01-identical at zero issues.
6. **Locale path** (on `new.page.finalUrl`; first path segment, else second; first locale-shaped
   match wins; links are NOT locale-checked — §10.2 is about "the path").
   - *Separated shape* `^([A-Za-z]{2,3})([-_])([A-Za-z]{2}|[0-9]{3})$`: structurally a locale →
     validate all three rules **independently** (each violated rule emits its own issue):
     - separator `_` → `locale_separator_invalid`
     - language not all-lowercase OR alpha region not all-uppercase → `locale_case_invalid`
     - case-normalized language ∉ ISO 639-1 OR alpha region ∉ ISO 3166-1 → `locale_unknown`
       (3-letter language subtags → `locale_unknown`: only 639-1 is embedded; documented
       approximation, revisit at M6 if a real pair uses 639-2 codes. 3-digit M49 regions are
       accepted unvalidated.)
     So: `es_MX` → separator only; `es-mx` → case only; `ES_mx` → separator + case; `xx-MX` →
     unknown.
   - *Bare shape* (2-letter alpha segment, no separator): treated as a locale **only if** its
     lowercase form is a known 639-1 language; then validate case only. Unknown bare segments are
     not locale-detected (prevents `api`/`img` false positives). Bare 3-letter segments are never
     locale-detected.
7. **Per-link trailing slash** (string-level, no network). For each same-site link on the new
   page (host equality with new page host, incl. port): resolved path ends in `/`, path ≠ `/`,
   policy `Never` → `url_trailing_slash` carrying the link node's anchors. **Parity-suppressed**
   when the old page has a link with identical host-stripped URL (path + query) — identical links
   are pre-existing, which keeps v01 clean.
8. **Per-link redirect chains** (from `new.page.linkProbes`). For each probe record passing the
   `egress.rs` guard, not `skipped`, with `redirectChain.len() > 1` → `url_redirect_chain` with
   the owning link node's anchors (node = lowest `seqIndex` whose fragment-stripped resolved
   href equals `probe.url`; BTreeMap join). No parity (a chain is a property of the new
   infrastructure; old side is not probed). Probe `error` records emit nothing in M2.

### 5.3 Issue construction (per type)

Common: category `hygiene` (except `status_code_mismatch` → `technical`), goal `G5` (url_*,
canonical) / `G6` (locale_*) / `null` (status_code_mismatch), severity from
`ParityProfile::severity_for` (hygiene → error under both profiles; status_code_mismatch →
critical), `locale` field = new page lang (existing convention), `styleProperty` = None in the
id hash. **Confidence:** new constants `base_confidence::HYGIENE = 0.98`,
`STATUS_CODE_MISMATCH = 0.99`, with **no environment/determinism multipliers** — hygiene facts
come from HTTP metadata, not rendering; the §5.4(M1) multipliers exist to discount
rendering-dependent evidence. Documented decision.

**Locators.** Page-URL-level issues (1–6): anchors all null **except `href` = the offending
path+query of the new final URL** (e.g. `/products/connect/branded-call/`) — a real grep target,
anchor strength high, and a stable id input. `bbox*`/`seqIndex*`/`cssSelector*` null. Per-link
issues (4b, 7, 8): the link node's full anchor set + internal locator fields
(`cssSelectorNew`, `bboxNew`, `seqIndexNew` from the node; old-side fields null — no matcher
until M3).

**Evidence / remediation shapes (normative for goldens):**

| type | evidence | remediation |
|---|---|---|
| `status_code_mismatch` | `{"old":{"statusCode":200,"url":<old finalUrl>},"new":{"statusCode":404,"url":<new finalUrl>}}` | `{action:"fix_route", findBy:{grep:[<new path>]}, from:"404", to:"200", note}` |
| `url_trailing_slash` | `{"new":{"url":<finalUrl or link url>,"path":<path>},"policy":"never"}` | `{action:"rewrite_url", findBy:{grep:[<path-with-slash>]}, from:<path-with-slash>, to:<path-without>, note}` |
| `url_redirect_chain` | `{"new":{"requestedUrl":…,"redirectChain":[…],"finalUrl":…,"hops":N}}` | `{action:"update_link_target", findBy:{grep:[<requested path>]}, from:<requestedUrl>, to:<finalUrl>, note}` |
| `url_protocol_downgrade` | `{"old":{"url":"https://…"},"new":{"url":"http://…"}}` | `{action:"rewrite_url", findBy:{grep:[<url sans scheme>]}, from:"http://…", to:"https://…", note}` |
| `canonical_mismatch` | `{"old":{"canonical":<raw>},"new":{"canonical":<raw>,"canonicalResolved":…,"finalUrl":…}}` | `{action:"update_canonical", findBy:{grep:["rel=\"canonical\""]}, from:<resolved>, to:<normalized finalUrl>, note}` |
| `locale_separator_invalid` | `{"new":{"url":…,"localeSegment":"es_MX","expected":"es-MX"}}` | `{action:"rewrite_url", findBy:{grep:["es_MX"]}, from:<full path>, to:<corrected full path>, note}` |
| `locale_case_invalid` | same shape, e.g. segment `es-mx` expected `es-MX` | same shape |
| `locale_unknown` | `{"new":{"url":…,"localeSegment":…,"unknownSubtag":"xx"}}` | `null` (no deterministic fix is known) |

Messages: fixed templates, no timestamps, page-derived strings length-capped (they already are in
the bundle).

### 5.4 URL normalization helpers (in `hygiene.rs`, unit-tested)

- `host-stripped` form = path + `?query` (no scheme/host/port/fragment) — used for old↔new link
  parity joins, because the migration pair always lives on different hosts.
- Comparisons never lowercase paths (locale case matters); hosts compare case-insensitively
  (the `url` crate normalizes).

### 5.5 Wiring (`lib.rs::analyze_viewport`)

```text
hygiene = hygiene_issues(old, new, viewport, profile)
diff_out = diff_images(...); save diff.png            // always — artifacts stay valid
if hygiene.short_circuit:
    issues = hygiene.issues                            // exactly [status_code_mismatch]
else:
    issues = visual issues (existing) ++ hygiene.issues
resolve_id_collisions; scores
```

**Scores:** `hygiene = 1.0 / (1.0 + hygiene_issue_count)` (matches the spec §7 example: one
hygiene issue → 0.5; deterministic, revisit at M6); `technical = 0.0` when short-circuited,
else `1.0`; `visual` unchanged (1.0 − pageChangedRatio; under short-circuit the visual diff
still runs, so the score reflects it — acceptable: scores are advisory, the decisive signal is
the critical issue; documented).

Note: with two viewports the same URL-level hygiene issue is emitted once per viewport with
distinct ids (viewport is in the id hash). Consistent with the per-viewport bundle-pair model;
the harness pins one viewport. Known behavior, not a bug.

### 5.6 Unit tests (Rust, must exist)

- Trailing slash: never/always/preserve × root-exemption × query preservation.
- Redirect chain: 0/1/2 hops; evidence chain content.
- Locale matrix: `es-MX` ok, `es_MX` sep, `es-mx` case, `ES-mx` case, `ES_mx` sep+case,
  `xx-MX` unknown, `es` bare ok, `api`/`img`/`products` not detected, `fil-PH` unknown
  (documented), second-segment detection (`/docs/es-MX/…`), digit region accepted.
- Canonical: mismatch fires; raw-parity suppression; trailing-slash-policy normalization;
  absolute and relative canonicals.
- Protocol downgrade: input pair; link twin join; no false positive when old is also http.
- Status parity: 200/404 → critical + short_circuit; 404/404 → nothing; 404/200 → nothing;
  0 handling.
- Per-link parity suppression keeps an identical-pages pair issue-free (synthetic bundles).
- `egress.rs`: scheme refusal, IP-literal range refusal (incl. 169.254.169.254, ::1, fd00::/8),
  localhost-input exception, host-scope check.
- Issue construction: ids stable across bbox/score jitter (anchors.href only), every emitted
  issue validates against `contract/diff-result.schema.json` (existing jsonschema dev-dep
  harness).

## 6. New fixtures (specs — `expected-issues.json` content is authored by the orchestrator)

All three follow the v14/v15 pattern: `site/` byte-identical to golden (symlink-free copy),
custom `serve.py` only, static and deterministic. run-all.py auto-discovers by directory.

- **v16-locale-lowercase** (:3016, G6): serves `site/` under
  `/es-mx/products/connect/branded-call` (200 direct, no redirect).
  `urlUnderTest: http://localhost:3016/es-mx/products/connect/branded-call`.
  Required: `locale_case_invalid` + goal G6 + remediation from contains `/es-mx/`, to contains
  `/es-MX/`. Forbidden: `locale_separator_invalid`, `locale_unknown`, `url_trailing_slash`,
  `url_redirect_chain`, `missing_*`, `changed_text`, `visual_region_changed`, `style_changed`.
- **v17-redirect-chain** (:3017, G5): `GET /start` → 301 `/mid` → 301 `/` → 200 (root serves
  `site/`, relative assets resolve naturally). `urlUnderTest: http://localhost:3017/start`.
  Required: `url_redirect_chain` + goal G5 + anchors hrefContains `/start` + remediation
  fromContains `/start`, toContains `localhost:3017/`. Forbidden: `url_trailing_slash` (root
  exemption negative test), `locale_*`, `missing_*`, `changed_text`, `visual_region_changed`.
- **v18-status-mismatch** (:3018, technical): `urlUnderTest http://localhost:3018/products/
  connect/branded-call` returns **404** with a small self-contained rendered error page
  (deliberately different content — exercises the suppression). Required:
  `status_code_mismatch`, minSeverity critical, evidence oldContains `200`, newContains `404`.
  `maxIssues: 1`, status `["fail"]`. Forbidden: `missing_*`, `changed_*`, `visual_region_changed`,
  `page_height_changed`, `url_*`, `locale_*`.

Knock-on watch: serving under a path prefix makes the page's relative links resolve under that
prefix (e.g. v16 `branded-call.html` → `/es-mx/products/connect/branded-call.html`-ish). The
per-link parity join is host-stripped so these links are *not* parity-suppressed — but none of
them carries a trailing slash or fires any M2 check, so no knock-on issues are expected. Probes
against the variant server return 200/404 without chains. Manifests declare
`knockOnEffects: []`.

## 8. Risks / decisions taken (summary)

- **D1** Probing in capture, new-side only, recorded as `page.linkProbes`; analyze stays pure.
- **D2** Hygiene issues emitted for the new side only; old side is baseline (interpretation of
  "run on the two input URLs").
- **D3** Canonical raw-value parity suppression (testbed golden has an off-canonical on both
  sides; §11 both-sides principle).
- **D4** Per-link trailing-slash parity suppression via host-stripped URL join.
- **D5** Locale: independent rule emission; bare segments only detected when known 639-1; only
  639-1 embedded (3-letter langs → `locale_unknown`); revisit at M6.
- **D6** "Redirect where none should" clause deferred until the §14 config file exists.
- **D7** Hygiene confidence has no env/determinism multipliers (HTTP facts, not rendering).
- **D8** `hygiene` score = 1/(1+n); `technical` = 0 on short-circuit. Advisory until M6.
- **D9** Short-circuit still writes diff.png (artifact validity) but emits exactly one issue.
- **D10** Registrable-domain scope via `tldts` in TS; Rust defensive guard is host+port
  equality + IP-literal ranges (DNS unavailable in a pure function). Port sensitivity was an
  implementation deviation, approved: it is more conservative and consistent with the per-link
  same-site rule (§5.2 item 7).

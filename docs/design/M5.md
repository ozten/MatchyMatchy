# M5 — Sequence / order diff (G3)

Spec coverage: §8 (sequence diff), §6.2 step 4 (seq-displacement candidates), §7.1–7.3
(issue contract, taxonomy: `component_reordered`, `component_swapped`), §3.3 / §15
(determinism invariants). Fixture: `v07-sections-swapped` (testbed matrix #10).

## 1. Problem shape

The matcher (M3) pairs nodes identity-first, so a moved section arrives at M5 as a set of
*matched pairs* whose `seq_index` changed — never as missing+added. But `SemanticNode`s are
leaf-grained (heading, text, link, image); a "component" in G3's sense (a `<section>`) is a
*span* of consecutive nodes that moved together. The differ must therefore:

1. recover component-grained blocks from node-grained pairs,
2. classify block movement as *exchange* (→ one `component_swapped`) vs *move*
   (→ `component_reordered` per moved block),
3. never let LIS asymmetry misclassify an exchange (see §3, step S4 — this is the subtle bit).

```rust
/// Minimum block displacement (in eligible-pair rank units) for a
/// `component_reordered` emission. Swaps (exchanges) are never thresholded.
pub const SEQ_MIN_DISPLACEMENT: u32 = 2;
```

## 3. Algorithm (deterministic, pure)

**S0 — eligible pairs.** Take `outcome.pairs` with `band == MatchBand::Matched` **and**
`stage == MatchStage::Identity` only. Uncertain pairings must not manufacture structural
claims (§3.3 stability). Assignment-stage pairs are likewise excluded from both emission *and*
the order model — their pairing was decided partly **by position** (the stage-2 tiebreak), so
reading seq-index displacement off them as evidence of movement is circular; among
identical-content duplicates (carousels, repeated logos) the matcher cannot know which copy
went where, and any displacement derived from such a pairing is noise by construction
(observed: v08-cta-removed, where a 2-node removal shifted positional tiebreaks and
assignment cross-pairs produced 8 phantom structure issues). Spec §8's premise — "the
identity-first matcher guarantees that moved components are still paired … regardless of
position" — is a statement about stage-1 matches; only those make displacement meaningful,
position-independent evidence. Unmatched nodes never appear here (missing/added are
semantic-diff territory; §8.4 forbids double-counting).

**S1 — order model.** Sort eligible pairs by `(old.seq_index, old.id)` → `old_rank = 0..n-1`.
Sort the same pairs by `(new.seq_index, new.id)` → `new_rank`. Result: permutation
`perm[old_rank] = new_rank`. Ranks — not raw `seq_index` — define contiguity, so gaps left by
unmatched/uncertain nodes cannot break block detection.

**S2 — block decomposition.** Group into maximal runs contiguous in *both* orders:
ranks `r, r+1` belong to one block iff `perm[r+1] == perm[r] + 1`. Each block is a component-
grained unit that moved (or stayed) as a whole. List blocks in old order `B_0..B_{m-1}`; let
`σ(i)` = position of `B_i` when blocks are sorted by new-rank start. If `σ` is the identity:
return no issues.

**S3 — swap detection (before LIS, this order matters).** Every pair `i < j` with
`σ(i) = j ∧ σ(j) = i` is an exchange → exactly one `component_swapped` for the pair
(`B_i` primary). This covers both adjacent swaps (v07) and far-apart swaps with a fixed middle
(`σ = [2,1,0]` → transposition (0,2)) — the M5 DoD's "far apart vertically" case. Note the
block decomposition guarantees `ABCD→CDAB` collapses to one swap of two 2-node-blocks, not two
transpositions. Mark transposition members consumed.

Why before LIS: for an exchange `[A,B] → [B,A]` with `|A| ≠ |B|`, every LIS keeps the larger
block and flags only the smaller as displaced — emitting `component_reordered`, which v07
explicitly forbids. Transposition detection on `σ` is symmetric and immune to that.

> **Amendment (build-time ruling).** For a 2-block permutation — e.g. rotation
> `[X,P,Q] → [P,Q,X]`, where S2 collapses P,Q into one block — S3 classifies the result as a
> transposition and emits `component_swapped`, not `component_reordered`. The two readings
> ("X moved past the PQ run" vs "X and the PQ run exchanged positions") are indistinguishable
> from the permutation alone; spec §8.3 defines a swap as "two components exchange positions
> (A↔B)", which a 2-block exchange literally is, and the swap issue carries both locators plus
> block extents (`nodeCount`, seq-index ranges), so neither reading loses information. The
> §6.4 test list below is corrected accordingly (the no-swap reorder test uses a permutation
> with no block-level transposition). Severity/classification tuning is revisited at M6.

**S4 — reorders.** Over the non-consumed block positions in old order, compute the longest
strictly-increasing subsequence of their `σ` values. LIS canonicalization: iterate ascending
old position, patience algorithm with lower-bound replacement and predecessor links; among
equal-length candidates this yields one deterministic chain — pin it with a unit test on an
ambiguous permutation. Non-consumed blocks outside the LIS are *moved*: emit one
`component_reordered` per block, **iff** `|new_rank_start − old_rank_start| > SEQ_MIN_DISPLACEMENT`
— strictly greater, per spec §6.2's "**exceeds** a threshold" (small drifts are extraction
jitter or knock-on shifts from nearby removals, not component moves). Blocks inside the LIS are never flagged, even when `σ(i) ≠ i` —
they kept relative order; the absolute shift is caused by the blocks that moved.

**S5 — determinism.** All sorts carry total-order keys terminating in node `id`. Confidence
aggregation (below) reduces in ascending `old_rank` order. No `HashMap` touches output;
evidence maps are `serde_json::Map` built in fixed key order.

## 4. Issue construction

**Block representative** `rep(block)` = the first `kind == "heading"` member by old
`seq_index`; if none, the first member by old `seq_index`. (Section blocks thus anchor on
their own heading — the strongest grep target.)

**Locator** (primary block): `anchors` = rep's old-node anchors; `bbox_old`/`bbox_new` =
component-wise min/max union over the block's member bboxes on each side;
`seq_index_old`/`seq_index_new` = rep's; `css_selector_old`/`css_selector_new` = rep's.

**`component_swapped`** (one per transposition; primary = block earlier in old order, "A"):
- `category: structure`, `severity: error`, `goal: "G3"`, `viewport` as passed.
- `confidence` = mean of member-pair `score` over A∪B in ascending `old_rank`, rounded 4 dp.
- `message`: `Components swapped: "{repA}" and "{repB}" exchanged document order; "{repB}" now renders before "{repA}".`
  (rep text = anchor text truncated to 80 chars, deterministic.)
- `evidence`:
  ```jsonc
  {
    "blockA": { "anchors": {...}, "bboxOld": [...], "bboxNew": [...],
                "seqIndexOldRange": [s,e], "seqIndexNewRange": [s,e], "nodeCount": n,
                "match": { "stage": "...", "score": 0.97, "signals": {...} } },  // rep pair
    "blockB": { /* same shape — this is the spec's "both locators" */ },
    "oldOrder": ["<repA text>", "<repB text>"],
    "newOrder": ["<repB text>", "<repA text>"]
  }
  ```
- `remediation`:
  ```jsonc
  { "action": "reorder_components",
    "findBy": { "grep": ["<repA text|href>", "<repB text|href>"], "near": "<repA nearestHeading>" },
    "expectedOrder": ["<repA text>", "<repB text>"],
    "note": "Restore original document order: \"A\" must precede \"B\". Grep targets may hit repo source or CMS content; the anchors identify the sections either way." }
  ```
- `id` = `compute_issue_id(ComponentSwapped, viewport, anchors_of_A, None)` — content-addressed
  per §7.1; B's anchors live in evidence, never in the hash.

**`component_reordered`** (one per moved block):
- Same category/severity/goal/confidence rules (confidence over the block's own pairs).
- `message`: `Component moved: "{rep}" moved from document position {old_rank_start} to {new_rank_start} of {n} matched components.`
- `evidence`: block descriptor (same shape as `blockA`), plus
  `"displacement": d`, `"movedBefore"` / `"movedAfter"`: anchor text of the old-order stable
  neighbor it should precede/follow (deterministic from old order; omit at sequence edges).
- `remediation`: `action: "reorder_components"`, `findBy` from rep,
  `"target"`: rep anchor text, `"before"` / `"after"`: old-order neighbor anchor texts,
  `"expectedOrder"`: `[after, target, before]` filtered for edges.
- `id` over the block's primary anchors, `style_property = None`.

## 6. Acceptance criteria

1. `make fixture VARIANT=v07-sections-swapped` passes its intent check: exactly the required
   single `component_swapped` (goal G3), zero `missing_*` for either swapped section, zero
   `component_reordered`. Status ∈ {warn, fail}.
2. All 18 previously-green variants stay green and all 18 existing goldens compare
   byte-identical (structure score change provably inert when no structure issues exist).
3. Determinism spot-check on v07: same bundles twice → byte-identical `DiffResult`.
4. Unit tests (new `mod tests` in `sequence_diff.rs`):
   - identity permutation → no issues;
   - adjacent two-block swap → single `component_swapped`, zero reorders (synthetic v07);
   - far-apart swap with stable middle (`σ=[2,1,0]`) → single `component_swapped`;
   - rotation `[X,P,Q]→[P,Q,X]` → single `component_swapped` of X with the PQ block
     (2-block exchange; see S3 amendment);
   - a multi-block move with no block-level transposition (e.g. node perm `[2,4,1,0,3]`)
     → `component_reordered` per displaced block, no swap;
   - two independent exchanges → two `component_swapped`;
   - `ABCD→CDAB` → ONE swap (block decomposition collapses it);
   - displacement exactly `SEQ_MIN_DISPLACEMENT` → suppressed; displacement
     `SEQ_MIN_DISPLACEMENT + 1` → emitted (strict-threshold boundary, spec §6.2 "exceeds");
   - multibyte anchor text straddling the 80-byte truncation boundary → no panic,
     char-boundary truncation;
   - uncertain-band pairs excluded (swap whose B-side pairs are Uncertain → no issue);
   - assignment-stage pairs excluded: cross-paired duplicate-content nodes (v08 shape —
     an assignment-stage transposition plus a large-displacement assignment-stage move)
     → zero sequence issues;
   - ambiguous-LIS permutation → pinned canonical displaced set (determinism);
   - id stability under bbox/score jitter (re-capture stability §7.1).
5. `Makefile` verify gate includes `v07-sections-swapped`; new golden
   `testbed/goldens/v07-sections-swapped.diffresult.json` recorded after intent pass and
   audited (golden-auditor) before commit.

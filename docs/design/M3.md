# M3 design — semantic extraction + content diff (G2, G7)

Spec: `docs/prds/page-pair-diff-spec.md` §12 M3, implementing §6 (matching) and the semantic-diff
portion of §11, governed by §3.3 (determinism/stability), §5 (anchors), §7 (contract), §15
(invariants). M1/M2 conventions (`docs/design/M1.md`, `M2.md`) carry forward unchanged.

## 1. Scope and DoD

M3 ships: the §6 identity-first two-stage matcher over the SemanticNode streams, and the
content/link/image diff deriving issues from matched pairs + leftovers. New issue types emitted:
`missing_title`, `changed_title`, `missing_meta_description`, `changed_meta_description`,
`missing_h1`, `changed_h1`, `heading_structure_changed`, `missing_text`, `changed_text`,

`missing_form`, `missing_form_field`, `missing_button`.

render-equivalent DOM changes (§13.2) with no false missing/added.

## 2. Contract deltas (capture-bundle only; DiffResult schema unchanged)

`SemanticNode` gains six fields, all emitted by capture for every node (null when not
applicable). JSON schema (`contract/capture-bundle.schema.json`), zod (`schema.ts`), and Rust
(`contract.rs`, `#[serde(default)]` so pre-M3 bundles still parse) all updated; schemaVersion

```jsonc
{
  "rawHref": "pricing.html",        // links: href attribute EXACTLY as authored; null otherwise
  "src": "http://localhost:3001/assets/images/x.png",  // images: currentSrc||src resolved absolute; null otherwise
  "naturalWidth": 600,               // images: intrinsic px; null otherwise

  "headingLevel": 1                  // headings: 1–6; null otherwise

```

`CaptureConfig` is unchanged, but the orchestrator now sets `probe_links: true` for **both**

## 3. The matcher (`src/matching.rs`) — the crux

Pure function: `match_nodes(old: &[SemanticNode], new: &[SemanticNode], page_ctx) ->
MatchOutcome`, where

```rust
pub struct MatchedPair {
    pub old_idx: usize, pub new_idx: usize,
    pub score: f64,                       // identity score (stage 1) or combined (stage 2)
    pub stage: MatchStage,                // Identity | Assignment
    pub band: MatchBand,                  // Matched | Uncertain
    pub signals: BTreeMap<String, f64>,   // per-signal sub-scores, 4-dp rounded
}
pub struct MatchOutcome {
    pub pairs: Vec<MatchedPair>,          // sorted by old seq_index
    pub missing_old: Vec<MissRecord>,     // unassigned old nodes + best_score evidence
    pub added_new: Vec<MissRecord>,       // unassigned new nodes (emit NO issues — D7)
}
```

`page_ctx` carries each side's final URL (host + page directory) for href normalization.

### 3.1 Blocking

Blocks by kind with ONE merge: `link` and `button` share a block (the spec's own weight table
has a single `link/button` row, and §13.2's render-equivalent case adds `role="button"` to an
anchor — a hard kind split would turn implementation changes into missing+added). Blocks:
`heading`, `link+button`, `image`, `field`, `form`, `text`, `generic` (fallback bucket).
Cross-block pairs are never considered (documented limitation: a heading demoted to a styled
div is missing+added; revisit at M6).

### 3.2 Stage 0 — exact-identity pre-pass (performance + robustness)

Within each block, group both sides by an exact identity key; when a key has **exactly one old
and exactly one new** node, pair them immediately (`stage: Identity`, `score: 1.0`, signals
`{"exactKey": 1.0}`). Keys per block:

```
heading:      (normalized text, headingLevel)
link+button:  (normHref ?? "", text ?? "", accName ?? "")
image:        (host-stripped src path, imageAlt ?? "")        // see D5
field/form:   (accName ?? "", role ?? "")
text/generic: (normalized text)
```

Non-unique keys (the 2× "Get a Demo", 7× G2 badges) fall through to scoring. The key uses the
same identity facts as the scorer, so a pre-pass pair is always one the weighted path would
accept; it just skips O(n²) similarity work for the ~95% trivially-identical case. The image
key intentionally adds `src` path equality, which the spec's weight table omits (see D5).

### 3.3 Similarity functions (all → [0,1], deterministic)

- `text_sim(a,b)`: both None → 1.0; one None → 0.0; equal → 1.0; else
  `0.5·token_jaccard + 0.5·(1 − levenshtein/max_len)` over normalized strings truncated to 200
  chars (capture already caps at 500); tokens = whitespace-split, ASCII-lowercased for
  comparison only.
- `href_sim(a,b)`: both None → 1.0; one None → 0.0; `norm(a) == norm(b)` OR raw hrefs equal
  → 1.0; host-stripped path+query equal → 0.9 (v11: external→local move, same path); same path,
  differing query → 0.7; else 0.0.
  `norm(link)` (siteness-aware, computed against the link's own page): same-site → resolved
  path+query relative to the page's directory when under it, else host-stripped path+query;
  external → full absolute URL; always fragment-stripped. This makes byte-identical authored
  hrefs compare equal even when the new page is served under a path prefix (v14–v16).
- `alt_sim`: text_sim over imageAlt (both-empty → 1.0 — agreement, not distinctiveness).
- `intrinsic_dim_sim`: `min(w)/max(w) · min(h)/max(h)`; either side 0 or null → 0.0 (a broken
  image shares no dimensions); both null → 0.5 (neutral).
- `role_sim`: equal (or both None) → 1.0 else 0.0.
- `nearby_sim`: `0.7·text_sim(nearestHeading) + 0.3·(landmark equal-or-both-None ? 1 : 0)`.
- `pos_sim = 1 − min(1, |y_old/H_old − y_new/H_new|)` (bbox y over page height);
  `size_sim` = bbox area ratio min/max (0 if either area 0).

### 3.4 Stage 1 — identity scoring (spec §6.2 weight tables, verbatim)

```
link/button: href .55  text .35  accName .10
image:       alt  .55  intrinsicDim .45
heading:     text 1.00
text:        text .85  nearby .15
form/field:  accName .55  role .30  nearby .15
generic:     text .70  role .30
```

For each unmatched old×new pair in a block compute `identity(a,b)`. A pair is matched
immediately (`stage: Identity`, `band: Matched`) iff `identity ≥ IDENTITY_FLOOR (0.85)` AND it
is the unique mutual best in its block: best-for-old and best-for-new, with the second-best on
*both* sides at least `TIE_MARGIN (0.05)` below. Position cannot veto these pairs (§6.2 hard
requirement). Iteration over candidates is in (old seq, new seq) order; the mutual-best scan is
order-independent because it compares scores, with `(old id, new id)` as the final total-order
tie-break on exact score ties.

### 3.5 Stage 2 — constrained assignment

Remaining candidates (identity ties — e.g. the duplicated CTAs — or identity < floor) go
through one-to-one assignment over

```
combined = 0.7·identity + 0.3·tiebreak,   tiebreak = 0.5·pos + 0.3·size + 0.2·nearby
```

Pairs with `combined < NO_MATCH_CEIL (0.45)` are forbidden. Solver: Hungarian
(maximum-weight, scores scaled to i64 nanounits — integral arithmetic, no float-comparison
ambiguity) for blocks where `max(n_old_rest, n_new_rest) ≤ 128`; above that, greedy: sort all
candidate pairs by `(-score_i64, old id, new id)`, accept while both endpoints free. Both are
deterministic total orders (§3.3). The spec's "prefers monotonic order" is carried by the
`pos` term; no extra constraint (documented).

### 3.6 Banding (spec §3.3 stability)

For every assigned pair: `score ≥ MATCH_FLOOR (0.70)` → `Matched`; `NO_MATCH_CEIL ≤ score <
MATCH_FLOOR` → `Uncertain`. Uncertain pairs are RETAINED as pairs (so no false missing/added —
this is what protects v12, where the broken image's intrinsic-dim signal collapses to 0) but
every issue emitted from them carries `confidence × UNCERTAIN_MULTIPLIER (0.6)` and
`evidence.match.band: "uncertain"`. Unassigned old nodes → `missing_old`; unassigned new →
`added_new`. Note: an old node whose best candidate was *consumed* by a better-scoring rival
(v08's hero CTA, identity 1.0 vs the surviving twin) is missing by assignment leftover even
though its best raw score exceeds the ceiling; `MissRecord.best_score` records it for evidence.

Thresholds live in `config.rs` as named constants (`IDENTITY_FLOOR 0.85`, `TIE_MARGIN 0.05`,
`MATCH_FLOOR 0.70`, `NO_MATCH_CEIL 0.45`, `HUNGARIAN_MAX 128`, `UNCERTAIN_MULTIPLIER 0.6`) —
plain constants, frozen only after M6 calibration.

### 3.7 Worked acceptance traces (sanity-check the numbers)

- **v13**: hero CTA old(kind link, role "link") / new(kind link — `a[href]` classification
  precedence keeps role=button anchors as links — role "button"). 2×2 identical keys → stage 2
  → position pairs hero↔hero, footer↔footer; identity 1.0, combined ≈ 1.0 → Matched; no
  attribute differs (raw href, text equal; role is not a diff signal) → zero issues. The
  display:contents wrapper produces no node (no box → bbox area 0).
- **v08**: two old "Get a Demo" links, one new. Stage 1: new node's best is tied (both
  identity 1.0) within TIE_MARGIN → stage 2. Hungarian: problem↔problem wins on pos (≈1.0 vs
  ≈0.77) and nearby (1.0 vs ≈0); hero old node left unassigned → `missing_link`, anchored
  hero (nearestHeading = the H1). Its inner text node likewise → an additional `missing_text`
  ("Get a Demo", hero) — legal, not forbidden by the fixture.
- **v09**: h1 pair leftover after identical headings pre-pair; textSim ≈ 0.65 → identity 0.65
  < floor → stage 2: combined ≈ 0.72 → Matched (or Uncertain if real sim lands below 0.70 —
  either way `changed_h1` is emitted; only its confidence differs). Forbidden `missing_h1` is
  page-level (new page still has an h1) and `missing_text` can't fire because the pair exists.
- **v11**: hrefSim 0.9 (host-stripped path equal, norm differs) → identity 0.945 ≥ 0.85,
  unique → stage-1 Matched. Emit `changed_link_target` (raw and norm both differ) +
  `broken_link` (new-side probe 404, old side has no same-site twin — its link was external).

## 4. Capture layer changes (TS)

`extract/page-model.ts`: emit the six new fields. `rawHref = el.getAttribute("href")` (links;
un-resolved, control-char-stripped + length-capped like other strings); `src = img.currentSrc
|| img.src` resolved absolute; `naturalWidth/naturalHeight = img.naturalWidth/Height`;
`loaded = img.complete && img.naturalWidth > 0`; `headingLevel` parsed from the tag. No other
extraction changes (classification, visibility, ordinals untouched — v13's wrapper handling
depends on the existing bbox-area-0 filter).

`schema.ts`: add the fields to `SemanticNodeSchema` (nullable, required). Update
`contract/capture-bundle.schema.json` to match (`required` includes them;
`additionalProperties` unchanged).

Tests (vitest): zod round-trip for a node with/without the new fields; schema rejects a node
missing them; normalization applied to rawHref.

## 5. Analyze layer changes (Rust)

### 5.1 New modules

- `src/matching.rs` — §3 above, plus the similarity functions (unit-test heavy).
- `src/semantic_diff.rs` — `pub fn semantic_issues(old: &CaptureBundle, new: &CaptureBundle,
  outcome: &MatchOutcome, viewport: &str, profile: &ParityProfile, env_mismatch: bool) ->
  Vec<Issue>` in fixed emission order (page-level checks, then per-pair diffs in old-seq order,
  then missing in old-seq order, then probe-derived broken_link in node-seq order).

### 5.2 Page-level checks (no matcher involvement)

Emitted with anchors all-null except where stated; no `evidence.match`; confidence
`PAGE_FACT (0.97)` with NO env/determinism multipliers (DOM metadata, not rendering — same
rationale as M2 hygiene/D7):

1. `missing_title` (old non-empty, new empty) / `changed_title` (both non-empty, differ).
2. `missing_meta_description` / `changed_meta_description` — same pattern.
3. `missing_h1`: old has a `headingLevel == 1` node, new has none. Anchors = old h1's anchors.
   (If both pages have h1s, h1 text changes are per-pair `changed_h1`, below.)

### 5.3 Per-pair attribute diffs (Matched and Uncertain pairs)

In old-seq order; all carry `evidence.match` = `{stage, score, band, signals}` (§6.2
auditability — spec §15 invariant). Confidence base: stage Identity → 0.95, stage Assignment →
0.90; × UNCERTAIN_MULTIPLIER when band Uncertain; × the standard env/determinism multipliers
(`compute_confidence`); × CHROME_PENALTY (0.85) when the new node's landmark ∈ {banner,
navigation, contentinfo} (the §11 "weight main-content over chrome" rule, D9). Anchors/locator:
NEW node anchors (the fix lives in the new page's source), both sides' selectors/bboxes/seq
indices.

| condition (on matched pair) | issue |
|---|---|
| heading pair, text differs, either side level 1 | `changed_h1` |
| heading pair, text differs, neither level 1 | `changed_text` |
| heading pair, level differs | `heading_structure_changed` |
| text/generic pair, text differs | `changed_text` |
| link/button pair, raw href differs AND norm(href) differs | `changed_link_target` |
| link/button pair, text differs | `changed_link_text` |
| image pair, old loaded && new !loaded | `broken_image` (suppresses the two rows below for that pair) |
| image pair, both loaded, alts differ, both non-empty | `changed_alt_text` |
| image pair, old alt non-empty, new alt empty/null | `missing_alt_text` |
| image pair, both loaded, dim ratio < 0.9 on either axis | `changed_image_dimensions` |

`broken_image` confidence: 0.95 with env/determinism multipliers (lazy-load dependent), NOT the
uncertain multiplier path alone — band multiplier still applies if the pair is uncertain.
The both-empty-alt case emits nothing (v12 notes: golden alt is empty on both sides).

### 5.4 Missing / added / broken_link

- Each `missing_old` record emits `missing_<kind>`: heading → `missing_text` (no
  missing-heading type; `missing_h1` stays page-level), text/generic → `missing_text`, link →
  `missing_link`, button → `missing_button`, image → `missing_image`, form → `missing_form`
  (severity **critical** — §13.1 fixture 5 — via a `severity_for` special case), field →
  `missing_form_field`. Anchors = OLD node anchors; locator old-side only; confidence 0.90 ×
  multipliers (× chrome penalty by old node's landmark); `evidence.match = {stage:
  "assignment", bestScore, band: "unmatched"}`.
- `added_new` records emit **no issues** (v1 taxonomy has no added_* types — D7; v02's banner
  is covered by visual_region_changed as its expectation documents).
- `broken_link`: for each new-page link node whose same-site probe record (join: lowest
  seq-index node whose fragment-stripped resolved href equals `probe.url`, as M2 §5.2.8) has
  `skipped: null` and `status ≥ 400` → emit UNLESS the old side shows the same failure:
  the node's matched old partner (if any) resolves to an old-side probe record with `status ≥
  400` or `error != null` → suppressed (spec §11 "failures on both are noted but not scored").
  Old partner external/unprobed/missing-record → emit. Confidence 0.98, NO env/determinism
  multipliers (HTTP fact, M2/D7 rationale). Category content, goal G7.
  This is why old-side probing turns on: on the identical pair the 3 pre-existing 404 links are
  suppressed by their old twins' identical 404s, keeping v01 at zero issues; v11's link has no
  old same-site twin (old href was external) so it fires.

### 5.5 Severity / category / goal

All M3 types: category `content`, goal `G2` — except `broken_link`, `broken_image`,
`changed_image_dimensions` → goal `G7`; `missing_form` severity critical (special case);
everything else takes `severity_for(content)` = error under both profiles. `locale` field =
new page lang (hygiene convention).

### 5.6 Evidence / remediation shapes (normative for goldens)

All evidence objects also carry `match` per §5.3/5.4 (absent on page-level issues). Direction
convention (as M1 gradient example): `from` = new (wrong) value, `to` = old (expected) value.

| type | evidence (beyond `match`) | remediation |
|---|---|---|
| `changed_title` / `changed_meta_description` | `{"old":{"title":…},"new":{"title":…}}` (or `metaDescription`) | `{action:"restore_text", findBy:{grep:[new value]}, from:new, to:old}` |
| `missing_title`/`missing_meta_description` | `{"old":{…},"new":null}` | `{action:"restore_text", findBy:{grep:[old value]}, from:null, to:old}` |
| `changed_h1` / `changed_text` / `changed_link_text` | `{"old":{"text":…},"new":{"text":…}}` | `{action:"restore_text", findBy:{grep:[new text], near:nearestHeading}, from:new, to:old}` |
| `heading_structure_changed` | `{"old":{"level":2,"text":…},"new":{"level":3,"text":…}}` | `{action:"restore_heading_level", findBy:{grep:[text]}, from:"h3", to:"h2"}` |
| `missing_h1` | `{"old":{"text":…},"new":null}` | `{action:"restore_content", findBy:{grep:[old text]}, from:null, to:old}` |
| `missing_text`/`missing_link`/`missing_button`/`missing_image`/`missing_form`/`missing_form_field` | `{"old":{"text"/"href"/"src"/"alt": …}}` | `{action:"restore_content", findBy:{grep:[old text and/or href/alt], near:nearestHeading}, from:null, to:old text/href}` |
| `changed_link_target` | `{"old":{"href":raw,"resolved":norm},"new":{"href":raw,"resolved":norm}}` | `{action:"update_link_target", findBy:{grep:[new raw href, link text]}, from:new raw, to:old raw}` |
| `broken_link` | `{"new":{"url":probe.url,"status":404},"old":{"url":…,"status":…}|null}` | `{action:"fix_broken_link", findBy:{grep:[new raw href, link text]}, from:new raw href, to:null, note}` |
| `broken_image` | `{"old":{"src","naturalWidth","naturalHeight","loaded":true},"new":{…,"loaded":false}}` | `{action:"fix_image_asset", findBy:{grep:[src filename, alt if any], near:nearestHeading}, from:new src, to:null, note}` |
| `changed_alt_text`/`missing_alt_text` | `{"old":{"alt":…},"new":{"alt":…}}` | `{action:"restore_text", findBy:{grep:[src filename]}, from:new alt, to:old alt}` |
| `changed_image_dimensions` | `{"old":{"naturalWidth","naturalHeight"},"new":{…}}` | null |

Messages: fixed templates, page-derived strings already capped/stripped (§7.5).

### 5.7 Wiring (`lib.rs::analyze_viewport`) and scores

After the hygiene short-circuit check (short-circuit skips ALL content diffing — v18 stays at
exactly one issue), before/independent of the visual pass:

```text
outcome = match_nodes(old.page.nodes, new.page.nodes, page_ctx)
content_issues = semantic_issues(old, new, &outcome, viewport, profile, env_mismatch)
issues = visual ++ content_issues ++ hygiene (existing order preserved for visual/hygiene)
```

`scores.content = 1/(1 + content_issue_count)` (the M2 hygiene formula — consistent, advisory
until M6); all other score formulas unchanged. v01/v02/v13–v18 must produce zero content issues,
keeping `content = 1.0` and their goldens byte-stable.

### 5.8 Unit tests (Rust, must exist)

- Similarities: text_sim (equal/None/disjoint/truncation), href_sim ladder incl. the v11
  (external→local, 0.9) and v14 (raw-equal under prefix, 1.0) shapes, intrinsic_dim (broken →
  0), nearby_sim.
- Pre-pass: unique-key pairing; non-unique keys (2v1, 2v2, 7v7) fall through.
- Stage 1: identity floor, mutual-best uniqueness, tie-margin defeat (v08 synthetic: two
  identical olds, one new → no stage-1 pair).
- Stage 2: Hungarian determinism (permuted input order → identical output), forbidden-pair
  ceiling, leftover→missing (v08 synthetic asserts the HERO node is the missing one), greedy
  path beyond HUNGARIAN_MAX with total-order tie-break.
- Banding: scores in [ceil, floor) → Uncertain, retained, confidence multiplied.
- §13.2 synthetic: link wrapped + role added → paired, zero issues.
- semantic_diff: each row of the §5.3 table; broken_image suppression of alt/dim rows;
  broken_link parity (old-404 suppressed, old-external emitted, old-200 emitted);
  page-level h1/title rules; missing_form → critical; chrome penalty applied by landmark;
  every emitted issue validates against `contract/diff-result.schema.json`; evidence.match
  present on all matcher-derived issues; issue ids stable across bbox/score jitter.

## 8. Risks / decisions taken

- **D1** Blocks by kind with link+button merged (spec weight table has one link/button row;
  §13.2 demands it). Cross-block moves (heading→div) are missing+added; M6 revisit.
- **D2** Thresholds: MATCH_FLOOR 0.70, NO_MATCH_CEIL 0.45 (spec gives no numbers; chosen so
  heavy text edits land Matched/Uncertain — emitted as changed_* either way — while unrelated
  text (identity ≲ 0.5 → combined < 0.45) cannot pair. Frozen after M6.)
- **D3** Link identity & changed_link_target use the as-authored `rawHref` plus a
  siteness-aware normalized resolved form; `changed_link_target` requires BOTH to differ.
  Rationale: prefix-served variants (v14–v16) and host migrations must not flood; v11's
  external→local rewrite must fire. New capture field `rawHref`.
- **D4** Link probing now runs on BOTH sides; broken_link is suppressed when the matched old
  partner's probe also failed (§11 both-sides principle). Verified necessary: the golden page
  itself has 3 dead same-site links on every pair, including v01.
- **D5** Image pre-pass keys on (src path, alt) — src equality (never similarity) pairs the
  v12 broken image at full confidence even though the spec's alt/intrinsicDim weights alone
  put a broken image in the uncertain band (intrinsicDim collapses to 0). The weighted scorer
  itself stays spec-verbatim. M6 revisit.
- **D6** Uncertain band → pair retained; changed_* emitted at ×0.6 confidence with
  `band: "uncertain"` in evidence (spec §3.3 "emitted with low confidence", never a coin-flip
  missing/added).
- **D7** Added new-side nodes emit no issues (taxonomy has no added_* types in v1); they
  surface via visual regions (v02's documented expectation).
- **D8** Unmatched old headings emit `missing_text`; `missing_h1` is page-level (old has h1,
  new has none). Keeps v09's forbidden missing_h1 structural, not matcher-dependent.
- **D9** "Weight main-content over chrome" (§11) = confidence ×0.85 for content issues whose
  anchor landmark is banner/navigation/contentinfo. Severity untouched. M6 revisit.
- **D10** Deferred types (§1) have no fixture and (forms) no possible golden-page fixture —

- **D11** content score = 1/(1+n), mirroring M2's hygiene formula; advisory until M6.
- **D12** Assignment-leftover olds are `missing` even when their best raw score was high (the
  candidate was consumed) — spec §6.2's "below noMatchCeil against all candidates" describes
  the no-candidate case; one-to-one assignment is what makes v08 correct. `best_score` is
  recorded in evidence for auditability.
- **D13** (added during verification) Capture keeps an `<img>` node despite a zero-area bbox
  iff the image is broken (`complete && naturalWidth === 0`) and not CSS-hidden. Found via
  v12: a 404'd image with empty alt and no CSS dimensions renders at 0×0, so the §4.3
  "non-empty bbox" rule dropped it from the node stream entirely — the analyze layer then saw
  a *disappeared* element and emitted `missing_image`, which is factually wrong (the element
  is still in the DOM; its asset is broken). A deliberate, narrowly-scoped exception to §4.3:
  broken-but-present images are page defects — precisely G7's quarry — not invisible content.
  With the node present, the D5 src pre-pass pairs it at full confidence → `broken_image`.
- **D14** (added during verification) `nearestHeading` extraction rule refined: use the most
  recent document-order-preceding visible heading ONLY when it lies inside the node's nearest
  `<section>` ancestor; when the node's section contains headings but the preceding heading is
  outside it, use the section's FIRST visible heading (its title) even though it follows the
  node; nodes with no `<section>` ancestor (or a heading-less section) keep the M1
  preceding-heading rule. Found via v12: the analytics `<img>` precedes its section's heading
  in the DOM (image-left/heading-right layout), so the M1 rule anchored it to the *previous*
  section — a misleading locator. The §5 anchor set exists to locate the element; the section's
  own title is the locator a human would give. Heading nodes keep anchoring to themselves
  (first-of-section resolves to self). Code fix, not an expectation change.

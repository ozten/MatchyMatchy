# SiteDiff vs matchy — Benchmark Report

> Generated by the [MatchyMatchBenchmark](README.md#reproducing) harness (`sitediff-bench/run.py`). SiteDiff [evolvingweb/sitediff](https://github.com/evolvingweb/sitediff) v1.2.11 vs matchy (page-pair-diff). Corpus: the matchy testbed — 21 single-change old→new page pairs (golden `:47000` vs one variant per port), each with hand-authored ground truth.

## TL;DR

- **SiteDiff** is an HTML *text* differ (HTTP fetch, no browser, no JS). On the 16 in-model variants it detected **8/14** real regressions and produced **1** false positive(s) on the 2 render-identical controls.
- **matchy** renders both pages (Playwright) and emits typed, located defects. It surfaced **14/14** regressions and produced **0** false positives on the controls.
- SiteDiff is **blind to every change that doesn't alter the HTML source**: CSS-only visual regressions and a deleted image whose `<img src>` is unchanged. It also **false-positives** on a render-equivalent DOM rewrite (markup changed, pixels didn't).
- SiteDiff is **structurally unable to express** the 5 URL-transport variants (trailing-slash, locale casing, redirect chains, status mismatch) — it compares the *same path* on two base URLs, but those defects change the URL/transport itself.

## Methodology

Both tools receive the identical old/new pair. **old** is always the golden page (`http://localhost:47000/`); **new** is the variant under test.

- **SiteDiff**: a per-variant config (`before.url` / `after.url`) + a one-line `paths.txt` (`/`), run as `sitediff diff`. Verdict = *changed* iff `failures.txt` is non-empty (exit 2); *unchanged* iff exit 0. This is SiteDiff's own native signal.
- **matchy**: its `DiffResult` for the same pair (the committed testbed goldens, byte-deterministic; reproducible with `make fixture VARIANT=…`). *Surfaced* = the DiffResult contains ≥1 issue (typed semantic defect and/or visual-region issue).
- A variant is **in-model** if golden and variant serve the page at the same path (`/`) so SiteDiff's same-path model applies; **out-of-model** if the defect is a URL/transport property that moves or rewrites the path itself.

## The 5 out-of-model variants (URL / transport)

These defects live in the URL or HTTP transport, not in same-path page content. SiteDiff compares the *same path* on two base URLs, so it cannot be pointed at “golden `/`” vs “variant `/es_MX/products/connect/branded-call`”. For completeness the runner still attempts a naive root compare; the result is either a miss or a *spurious* change (root simply isn't served), never a real detection of the defect.

| Variant | Transport defect | matchy detects | SiteDiff (same-path model) |
|---|---|:--:|---|
| `v14-trailing-slash` | GET without trailing slash 301-redirects (trailing-slash policy) | ✅ url_trailing_slash | ❌ root path not served (404) → SiteDiff sees a transport error, never the defect |
| `v15-locale-underscore` | locale `es_MX` uses an underscore separator | ✅ locale_separator_invalid | ❌ root path not served (404) → SiteDiff sees a transport error, never the defect |
| `v16-locale-lowercase` | locale `es-mx` lowercases the region subtag | ✅ locale_case_invalid | ❌ root path not served (404) → SiteDiff sees a transport error, never the defect |
| `v17-redirect-chain` | two-hop 301 redirect chain at `/start` | ✅ url_redirect_chain | ❌ defect lives at a sub-path, invisible at root → flags only an incidental content delta |
| `v18-status-mismatch` | new URL returns HTTP 404 (status parity) | ✅ status_code_mismatch | ❌ root path not served (404) → SiteDiff sees a transport error, never the defect |

## Capability matrix

| Capability | SiteDiff | matchy |
|---|:--:|:--:|
| Fetch / render | HTTP only (no JS, no browser) | Headless Chromium (Playwright), JS executed |
| Content & copy changes | ✅ line-level markup diff | ✅ typed `missing_text` / `changed_h1` / … |
| Structure reorder | ✅ (as add+remove) | ✅ `component_swapped` (reorder, not add+remove) |
| CSS-only visual change | ❌ invisible | ✅ `style_changed` / `background_gradient_lost` |
| Deleted asset, same `src` | ❌ invisible | ✅ `broken_image` + `network_error` |
| Render-equivalent DOM rewrite | ❌ false positive | ✅ matched, stays quiet |
| Broken links | partial (only if href text changes) | ✅ probes target, `broken_link` |
| HTTP status / redirects | ❌ | ✅ `status_code_mismatch`, `url_redirect_chain` |
| Trailing-slash / locale hygiene | ❌ | ✅ `url_trailing_slash`, `locale_*` |
| Console errors | ❌ | ✅ `console_error` |
| Accessibility regressions | ❌ | ✅ `accessibility_regression` (axe-core) |
| Output | HTML diff report (human review) | Typed JSON `DiffResult` (agent/CI-actionable) + HTML/MD |
| Crawl / many paths | ✅ built-in crawler | ❌ single explicit pair (v1) |
| Noise suppression | ✅ regex/dom_transform rules | ✅ confidence bands, `--hide`/`--mask`, `--baseline` |
| Maintained | ✅ v1.2.11 (Aug 2024) | ✅ in active development |

## Where SiteDiff is the better tool

- **Scale across many paths.** SiteDiff crawls and diffs hundreds of URLs from one config; matchy v1 takes a single explicit pair. For broad migration coverage, SiteDiff's crawler is a real advantage.
- **Exact markup deltas.** When content *did* change, SiteDiff's line-level before/after diff shows the precise markup edit — for `v02-banner-added` it names the added `<div>`, whereas matchy reports only visual regions + a height change.
- **No browser dependency.** Pure HTTP means trivial install and fast runs in any CI.
- **Mature normalization.** Years of regex/`dom_transform` rules for stripping CSRF tokens, timestamps, and ad params.

## Where matchy wins

- Catches the **6 in-model regressions SiteDiff is blind to** (5 CSS-only + the deleted image), with a typed, fixable issue for each.
- **No false positive** on the render-equivalent rewrite that trips SiteDiff.
- Owns an **entire class** SiteDiff has no concept of: HTTP status, redirect chains, URL/locale hygiene, console errors, accessibility — the 5 out-of-model variants plus console/a11y, all detected.
- Emits **machine-actionable** typed defects (greppable anchors + structured remediation) rather than an HTML diff a human must read.

## Honest takeaway

SiteDiff and matchy are **complementary, not redundant**. SiteDiff is a wide-coverage HTML-text differ — excellent at finding *content/markup* drift across a whole site, and lighter to run. matchy is a deep, single-pair *rendered+semantic* differ — it sees CSS, assets, transport, runtime, and a11y that never touch the HTML source, types every defect, and avoids the markup-noise false positives that HTML-text diffing produces. A migration team could reasonably use SiteDiff for broad crawl coverage and matchy for deep per-page verification of the pages that matter.
